# 仕様書 05: サーバーエンコーダ・マルチ GPU・負荷プロファイル

> 関連: Issue #11, Issue #99

## 1. 概要と目的

多様なホスト環境（NVIDIA NVENC / AMD Radeon / Intel iGPU / Windows Docker Desktop D3D12 / CPU のみ）においてハードウェア支援エンコードを自動判定・活用し、非対応環境でも確実にソフトウェアエンコードへフォールバックする。またサーバー演算負荷と確定済みの車載端末負荷プロファイル（MCU3 / MCU2）を独立して最適化し、単一マスタークロックと世代 ID（`streamEpoch`）に基づく低遅延配信を実現する。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 映像・音声デュアルエンコード & サーバー AVCC オフロード
- **映像エンコード要件**:
  - 仮想ディスプレイ（X11、マウスカーソル非描画）を指定 FPS・ビットレートでキャプチャし、B フレーム `0`・GOP 長 `max(1, round(fps * 2.0))`（2 秒間隔）・`maxrate = 1.3x`・`bufsize = 0.6x` の超低遅延 H.264 ストリームを生成する。
  - すべてのバックエンド（**VAAPI・NVENC・Software 共通**）で、クライアント負荷プロファイルに基づく縮小エンコード（スケーリングフィルタ）をサポートする。
  - エンコーダ出力の Annex-B ストリームをサーバー側でパースし、AUD（NAL 9）と SEI（NAL 6）を破棄、SPS（NAL 7）/ PPS（NAL 8）を 4 バイト開始コードへ正規化して `CONFIG` フラグ付き（PTS=0）で先行送出し、同一アクセスユニット内の全スライスを 4 バイト Big-Endian 長ヘッダ付きの単一連続 AVCC バッファへ結合して `AVCC` フラグ（および IDR 時は `KEYFRAME` フラグ）で配信する。
- **音声エンコード要件**:
  - PulseAudio 仮想シンクのモニタ出力を映像プロセスと連携しつつ独立して `libopus`（20ms フレーム・VBR・`lowdelay`・フラッシュ有効）エンコードし、OggOpus ページから `OpusHead`（19 バイト以上）を `CONFIG` として送出、`OpusTags` をスキップ、生 Opus パケットを 20ms 単位で配信する。
  - 音声キャプチャの FFmpeg 入力デバイス指定は `-f pulse -i default` とする。libpulse バックエンドは `default` でデフォルトシンクのモニタを解決するため、具体的なシンク名（`virtual_sink.monitor` 等）や `default.monitor` の直書きを禁止する（後者は Input/output error で起動失敗）。
  - 音声ビットレートのみの変更時は映像プロセスを止めず、映像のみの設定変更時は音声プロセスを止めない（ただしサーバー側リセット / 電源復帰時は双方を同時再起動して同期させる）。
- **単一マスタークロック・世代 ID & ライフサイクル**:
  - 映像・音声エンコーダは単一のマスタークロック基準および単調増加するストリーム世代 ID（`streamEpoch`）を基準として PTS を採番し、独立プロセス間の初期・定常タイムスタンプスキューを防ぐ。
  - 映像フレーム出力が `3,000 ms` 以上停止した場合はウォッチドッグにより映像プロセスを自動再起動する（意図的停止・Buffer-Hold 中を除く）。
  - プロセス停止時は `SIGTERM` を送信し、`80 ms` 以内に終了しなければ `SIGKILL` へエスカレーションする。再起動時は `100 ms` 待機して再生成する。

### 2.2 マルチ GPU 自動検出 & 段階フォールバック
- **動作モード (`ENCODER_MODE`)**: `auto`（既定） / `nvenc` / `vaapi` / `software`。
  - コンテナ起動スクリプトを含め `ENCODER_MODE=nvenc` を正式に受理し、固定モード指定時は他バックエンドへ自動降格せず失敗理由を明確に警告・リトライする。
- **起動時バックエンド選択優先順位（`auto` モード時）**:
  1. **NVIDIA (`h264_nvenc`)**: NVIDIA デバイス露出確認（`NVIDIA_VISIBLE_DEVICES` が `none`/`void` 以外で非空、または `/dev/nvidiactl` / `/dev/nvidia0` 存在）の上、稼働時と同一の低遅延構成（`-preset p1 -tune ll -zerolatency 1`、入力 `256×144:r=1`、`-pix_fmt yuv420p`）で 1 フレームの `h264_nvenc` 実エンコードプローブ（8 秒タイムアウト）に成功した場合は **最優先で NVENC を採用** する。
  2. **AMD (VAAPI `radeonsi`)**: `/dev/dri/renderD*` を走査し、AMD ベンダ（`0x1002`）ノード上で `vainfo`（3 秒タイムアウト）の同一行に `VAProfileH264...VAEntrypointEncSlice` が存在する場合に採用する。
  3. **Intel (VAAPI `iHD` → `i965`) / Windows WSL2 (`d3d12`)**: Intel（`0x8086`）ノードでは `iHD` で H.264 エンコード可否を実測し不可なら旧世代向け `i965` へフォールバックする。WSL2（`/dev/dxg` 存在時）は `d3d12` でプローブする（明示ユーザー指定ドライバがある場合は尊重）。
  4. **Software (`libx264`)**: 上記いずれのハードウェアエンコーダも利用不可の場合に自動採用する。
- **稼働中フォールバックラダー & リトライ**:
  - 映像プロセスがフレームを 1 枚も出力せず `5,000 ms` 未満で異常終了した場合、`auto` モードでは優先順に従い設定緩和・降格を行う（NVENC 失敗 → 利用可能な VAAPI または `software` へ降格、VAAPI 失敗 → `low_power` 無効化 → GPU 色変換無効化 → `software` へ降格）。
  - 再試行待機時間は `[1000, 2000, 4000, 8000, 10000] ms` の指数バックオフとし、1 フレームでも正常出力された時点でリセットする。音声プロセス異常終了時は `1,000 ms` 固定間隔で再起動する。

### 2.3 配信パラメータ境界・サーバー負荷プリセット
- **パラメータ許容範囲と既定値**:
  - 映像ビットレート: **`250,000〜2,000,000 bps`（`0.25M〜2.0M`、既定 `1,000,000 bps`）**。上限 `2.0 Mbps` を超える値は `2,000,000 bps` へクランプする。
  - 音声ビットレート: `128,000〜320,000 bps`（既定 `128,000 bps`、範囲外は HTTP `400`）。
  - フレームレート: `24〜60 fps`（既定 `30 fps`）。
  - レイアウト最大辺 (`maxSize`): `640〜1,920 px`（既定 `1,280 px`）。**`PUT /api/settings` による `maxSize` 更新時は次のクライアントリサイズを待たず即座に仮想ブラウザおよびエンコーダ寸法へ反映する**。
  - キャプチャ/レイアウト寸法アライメント: 幅 `8 px` 境界（下限 `640`）、高さ `2 px` 境界（下限 `360`、上限 `min(1080, maxSize)`）。クライアント幅 `< 1000 px` 時は DPR に応じた `1.25〜1.5` 倍スケーリングを適用する。エンコード解像度は実車利用の中心となる小窓表示（代表基準 `773×553 CSS / DPR 1.53`）を主対象に最適化しつつ、`1.53` 等の特定 DPR 値は直書きせず、実行時物理ピクセルとサーバー側アライメント計算で吸収する。
- **サーバー映像パフォーマンスプリセット（6 種）**:
  - GPU 稼働時（NVENC / VAAPI）: `high`（`maxSize=1920`, VAAPI 圧縮 `4`, GPU 色変換 ON）, `balanced`（既定: `maxSize=1280`, VAAPI 圧縮 `7`, GPU 色変換 ON）, `low_power`（`maxSize=960`, VAAPI 圧縮 `7`, GPU 色変換 ON）, `custom`。
  - CPU 稼働時（`software`）: `cpu_balanced`（`maxSize=1280`, `x264Preset=veryfast`）, `cpu_low_power`（`maxSize=960`, `x264Preset=ultrafast`）, `custom`。許可 x264 プリセットは `ultrafast / superfast / veryfast / faster / fast / medium`。
  - 非対応バックエンドのプリセット変更や未知プリセット名は HTTP `400` で拒否する。VAAPI 固有項目（圧縮優先度・VDEnc・GPU 色変換）は VAAPI 稼働時のみ有効とし、`nvenc` および `software` では無効化する（`low_power` プリセット名称は VDEnc `-low_power 1` ではなく軽量解像度設定であることを UI 上で明確に表現する）。

### 2.4 クライアント負荷プロファイル（Issue #11 確定仕様 / Issue #99 整理）
- **エンコード出力寸法計算と原子的状態更新**:
  - 倍率 `scale >= 1.0` の場合はスケーリングフィルタ無し（等倍）。`< 1.0`（クランプ範囲 `0.4〜1.0`）の場合は幅 `max(320, round(layoutW * scale)) & ~7`（8 の倍数切り下げ）・高さ `max(240, round(layoutH * scale)) & ~1`（2 の倍数切り下げ）を算出し、**VAAPI / NVENC / Software 全バックエンドへ一貫して適用** する。
  - エンコーダの現在出力寸法および倍率は、**エンコーダ再起動の成功後に原子的に確定・更新** し、再起動ログも更新後の実アライメント寸法と一致させる。
- **確定 3 プロファイル**:
  - `standard`（既定 / MCU3 推奨）: 倍率 `1.0`、HUD 選択可能 FPS `[24, 30, 60]`、連動既定ビットレート `1.0M`。
  - `lightweight`（**MCU2 実車報告にて確定**）: 倍率 **`0.65`**、HUD 選択可能 FPS **`[24, 30]`**、連動既定ビットレート **`0.5M` (`500 kbps`)**。
  - `custom`: 任意倍率 `[0.4, 1.0]`、任意 FPS 集合（`[24, 60]` の重複排除・昇順ソート、空または 24 未満のみの場合は `[24, 30, 60]` へフォールバック）、任意既定ビットレート（任意、`[250k, 2.0M]` クランプ）。設定 UI の再設計仕様は [07-ui-hud-settings.md](07-ui-hud-settings.md) で定義する。

## 3. 非機能要件・制約条件

- **ドライバ設定ファイル保護**: `/etc/libva.conf` に特定ドライバ名を直書きしてはならず、実行時の自動判定およびユーザー明示指定を常に優先する。
- **D3D12 環境変数の厳格スコープ**: Windows Docker Desktop / WSL2 環境向けの `GALLIUM_DRIVER=d3d12` は、FFmpeg エンコーダおよび `vainfo` プローブのサブプロセス環境のみに限定し、仮想ブラウザプロセスへは絶対に付与しない。
- **情報セキュリティ**: ヘルス API やステータス表示文字列へプライベート IP アドレスやホスト固有の絶対パス等を露出しない。

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **固定モードでのデバイス不在／プローブ失敗**: `ENCODER_MODE=nvenc` または `vaapi` 固定時は `software` へ自動降格せず、失敗理由を明示警告した上で当該バックエンドでリトライする。
2. **D3D12 の VideoProc のみ対応 GPU**: `/dev/dxg` が存在しても `vainfo` でエンコードエントリポイントが見つからない GPU は VAAPI 非対応とみなし、`auto` なら安全にソフトウェアへフォールバックする。
3. **1 バイト単位のストリーム分断と AUD 欠落**: Annex-B H.264 がチャンク境界で任意長に分断された場合や AUD NAL が欠落した場合でも、次のスライス・SPS 境界で安全に Access Unit をフラッシュする。
4. **不正なプロファイル指定**: `clientProfile` に `null` や配列、未定義プロファイル名を指定した更新要求は HTTP `400` で拒否する。
5. **リサイズ待機中のプロファイル変更**: クライアントからのリサイズデバウンス待機中に負荷プロファイルが変更された場合、タイマー発火時点の最新倍率を用いてエンコード寸法を再計算する。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (マルチ GPU 優先順位 NVENC → AMD → Intel → Software & 固定モード)**:
  - **Given** NVIDIA NVENC・AMD (`radeonsi`)・Intel (`iHD` / `i965`)・WSL2 `/dev/dxg`・GPU なし環境
  - **When** `auto` モードおよび `ENCODER_MODE=nvenc` / `vaapi` 固定モードでエンコーダを起動する
  - **Then** `auto` では NVIDIA NVENC → AMD VAAPI → Intel VAAPI → `libx264` の順で選択され、`nvenc` 固定時は起動スクリプトを含め上書きされず固定動作し、起動失敗時は指数バックオフで段階フォールバックする。
- **AC-02 (AVCC 単一パス変換 & 2.0 Mbps 上限 & `maxSize` 即時反映)**:
  - **Given** 分断された Annex-B H.264 / OggOpus ストリームおよび稼働中のエンコーダ
  - **When** パース・パッキングを実行し、`PUT /api/settings` でビットレート `> 2.0M` または `stream.maxSize` 変更を送信する
  - **Then** SPS/PPS 分離・AUD/SEI 破棄・単一 AVCC 結合が行われ、映像ビットレートは `2.0 Mbps` へクランプされ、`maxSize` 変更は次リサイズを待たず即座に仮想ブラウザ・エンコーダへ反映される。
- **AC-03 (全バックエンドでの縮小エンコード & 原子的更新)**:
  - **Given** VAAPI / NVENC / Software のいずれかで稼働中のエンコーダ（レイアウト `966×752`）
  - **When** 確定済み `lightweight` プロファイル（`0.65` 倍、`24/30fps`、`0.5M`）へ切り替える
  - **Then** いずれのバックエンドでも `624×488` へスケーリング出力され、FPS スナップおよびエンコーダ再起動が 1 回に統合され、再起動完了後に内部状態が原子的に更新される。
- **AC-04 (音声独立再起動 & ウォッチドッグ)**:
  - **Given** 稼働中の映像・音声エンコーダ
  - **When** 音声ビットレートのみ変更する／意図的停止以外で映像出力が 3 秒以上途絶える
  - **Then** 音声ビットレート変更時は映像プロセスが無停止で維持され、3 秒途絶時はウォッチドッグが映像エンコーダを自動再起動する。音声プロセスの起動引数は `-f pulse -i default` であり（`default.monitor`・具体シンク名の直書き禁止）、音声再起動間隔は `1,000 ms` とする。
