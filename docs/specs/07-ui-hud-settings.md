# 仕様書 07: 車載 UI・常設 HUD・設定コンソール・お気に入り

> 関連: PR #102, Issue #101

## 1. 概要と目的

テスラ車載ディスプレイ（15/17 インチ）の完全タッチオンリー環境において、実車利用の中心となるナビ等と並べた **小窓表示（代表基準 `773×553 CSS` / DPR `1.53` 相当）** を主対象として UI 視認性・操作性およびエンコード解像度を最適化する。物理キーボードやマウスを一切使用せず、かつ車両ブラウザ側の `localStorage` に設定を持たせずサーバー保存に一元化した上で、1〜2 タップで動画視聴・サイト切り替え・YouTube 検索・画質調整・文字入力・省電力管理を完結できる直感的な UI を提供する（将来のファームウェア更新に伴う DPR 変化は固定値直書きを行わず実行時の物理ピクセルおよびサーバー側リサイズ計算で吸収する）。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 常設上部 HUD（ヘッドアップディスプレイ）
- **配置・操作性**:
  - 映像ビューポートの上部（DOM 構造上もビューポートより前）に常設配置し、車載ソフトウェアキーボード展開時の隠蔽および小窓表示（`773×553 CSS` 基準）を含む狭い画面幅での左側見切れを防ぐ安全な中央揃えレイアウトとする。
  - UI の文字サイズ・余白・コントロール密度・視認性は小窓表示（`773×553 CSS` 基準）を主対象として最適化し、全画面表示時にも破綻なく追従させる。またキャンバス描画およびリサイズ通知には特定 DPR（`1.53` 等）を固定値として直書きせず、実行時の物理ピクセル（`devicePixelRatio`）を用いる。
  - アクティブ状態のまま操作が無い場合は **4,000 ms** 後に自動減光する。
  - 更新・ブラウザ全画面・フィット・ミュート・HUD 非表示ボタン等の不要ボタンは配置しない。
- **左側コントロール群（状態表示・同期・品質切替）**:
  1. **停止ボタン**: 省電力＆リソース制御モーダルを開く（即時停止はしない）。
  2. **通信状態 & RTT バッジ**: 4 段階シグナルメーター＋状態ドット＋数値表示（切断 / 一時切断 / 1,200 ms 超未着で瞬断警告 / 400 ms 超未着または RTT 90 ms 以上で遅延警告 / 正常。有効 PONG 5 秒未着で「接続中」へ鮮度リセット）。
  3. **LIVE / バッファ状態ボタン**: 優先順に従い `HOLD L:x.xs S:x.xs` ＞ `DIRECT LIVE` ＞ `WAIT L:x.xs S:x.xs` ＞ `BUF L:x.xs S:x.xs`（ローカル `>= 800 ms` またはサーバー `>= 600 ms`）＞ `LIVE (+Nms)` ＞ `LIVE` を表示する。タップで単一の配信リセット API（`POST /api/stream/reset`、[03-streaming-transport.md](03-streaming-transport.md)）を実行し、常に映像・音声双方をリセットしてライブ同期する（**1,000 ms** 連打ガード付き、後席待機中は無効）。
  4. **実測描画 FPS バッジ**: 1,500 ms 以上描画更新が無ければ「静止中」、それ以外は `<fps> FPS` を表示する（目標 FPS の 80% 以上で正常色、未満で警告色）。
  5. **FPS クイックトグル**: サーバーから解決されたクライアント負荷プロファイル許可値（例: `[24, 30, 60]` または `[24, 30]`）を循環切替し、300 ms デバウンスで `PUT /api/settings` へ保存する。
  6. **ビットレートクイックトグル**: `0.25M / 0.5M / 0.75M / 1.0M / 1.5M / 2.0M` の 6 段階（`250k〜2,000k bps`、システム上限 `2.0 Mbps` と一致）を循環切替し、300 ms デバウンスで保存する（選択肢外の値が設定されている場合は次タップで `1.5M` へ進む）。
- **右側コントロール群（入力・ナビ・設定）**:
  7. **仮想キーボードドロワー**: お気に入りドロワーと相互排他で開閉。開くと編集可能属性（`user-select: text`）付き DOM `<input>` へ同期フォーカスして車載ソフトウェアキーボードを起動し、「送信」「Enter ⏎」「⌫」「Tab ⇥」「閉じる」を備える。
  8. **戻るボタン**: ブラウザ履歴を 1 つ戻る。
  9. **ホームボタン**: お気に入りで「ホーム」に設定された URL へ遷移する。
  10. **お気に入りドロワー**: 仮想キーボードドロワーと相互排他で開閉。「＋ 現在のページを追加」「編集 / 管理」「閉じる」および登録済みお気に入り一覧（ホームバッジ付き、1 タップで遷移し自動でドロワーを閉じる）を表示する。
  11. **YouTube 専用検索バー**: 現在表示中の URL ホストが厳密に `youtube.com` / `*.youtube.com` / `youtu.be`（`http:` / `https:`）である場合のみ表示し、それ以外や偽装ドメインでは誤操作防止のため非表示とする。`http(s)://` URL 入力時は直接遷移、検索語入力時は YouTube 検索結果 URL へ遷移する（フォーカス時幅 `120px -> 160px` 拡張）。
  12. **設定ボタン**: 設定・管理コンソールモーダルを開く。未認証時はネイティブ `window.prompt()` を使わず **アプリ内ソフトウェア PIN テンキーモーダル** で再認証する。
- **ビューポート状態オーバーレイ**: 起動中・スリープ中（オーバーレイまたは復帰ボタンのタップ [800 ms デバウンス] で [10-power-lifecycle.md](10-power-lifecycle.md) の復帰 API を呼出、および切断ボタン）・復帰中・切断中・後席待機中（切断ボタンのみ、タップ復帰無効）を全画面表示する。

### 2.2 省電力 & リソース制御モーダル
- 停止ボタンから開くモーダルに以下の 3 アクションを集約する（一時停止・再開・再エンコードの個別ボタンは置かない。閉じるボタンまたは背景タップで閉じる）:
  1. **ワンタップ停止**: [10-power-lifecycle.md](10-power-lifecycle.md) の停止 API を呼び出し、クライアントデコーダをリセットしてスリープオーバーレイを表示する（後席待機中は無効）。
  2. **ブラウザ＆配信再起動**: ネイティブ `window.confirm()` を廃止し、**アプリ内タッチ確認モーダル（または 2 タップ確認）** を経て [10-power-lifecycle.md](10-power-lifecycle.md) のブラウザ再起動 API を実行する（後席待機中は無効）。
  3. **セッション切断**: 明示切断通知を送信し、セッションストレージを消去して WebSocket を正常終了（コード `1000`）し、ページをリロードする（常時有効）。

### 2.3 お気に入り & ホーム管理
- **既定プリセット（11 サイト・既定ホーム: `youtube`）**:
  - `YouTube`（先頭）, `TVer`, `Prime Video`, `Netflix`, `ABEMA`, `Disney+`, `U-NEXT`, `DAZN`, `ニコニコ動画`, `Twitch`, `Google 検索`。
- **制約とルール**:
  - 最大 **100 件**。各項目は空でない一意の `id`・空でない `title`・`http:` または `https:` の有効な `url` を必須とし、違反時は HTTP `400` で拒否する。
  - **重複 URL の完全拒否**: 「現在のページを追加」「手動追加」「編集」「設定保存 API (`PUT /api/settings`)」の **全経路で同一 URL の重複登録を拒否** する。
  - 表示時は必ず HTML/XSS エスケープする。
  - **ホームと並び順**: ホーム変更時は対象項目を一覧の **先頭（index 0）** へ固定し他項目の相対順序を保つ。新規追加時はホームが先頭にあれば **index 1**（ホームが先頭以外なら **index 0**）へ挿入する。ホームに指定されていた項目が削除された場合は、残存リストの先頭項目（空なら `youtube`）へ自動フォールバックする。
  - **プリセット初期化**: 誤操作防止のため **5 秒以内の 2 タップ確認** を要求し、初期 11 サイト（YouTube ホーム先頭）へ戻す。

### 2.4 設定・管理コンソール（PIN 認証付き 3 タブ・サーバー一元保存）
- **Single Source of Truth 原則**: 車両ブラウザ側の `localStorage` の使用を完全に廃止し、拡大率・音声ビットレート・先行バッファ深度・詳細テレメトリ有効化などすべての設定をサーバー設定として一元保存・管理する（クライアントは接続時・設定表示時にサーバーから読み出す。また規定値を定義する設定定義コードを一箇所へ固めて保守性を高める）。モーダルおよびタブ UI の可読性・タップ領域も小窓表示（`773×553 CSS` 基準）を主対象として設計する。
- 電源操作・再エンコード・FPS/ビットレート変更・テスト音声・ログダウンロードのボタンは配置しない。モーダルの設定変更時はカスタムイベントでアクティブな HUD（お気に入り・ホーム・許容 FPS・表示設定）へ即時反映する。
- **タブ 1 — Web ブラウザ**: 任意 URL 直接移動（`http(s)` のみ）、お気に入り一覧からの 1 タップ移動・ホーム設定・上下並び替え・編集・削除・手動追加・現在ページ追加・プリセット初期化。
- **タブ 2 — 一般・配信設定**:
  - **選択肢コントロールはタッチ専用カスタムピッカー**: タブ 2 の選択肢コントロール（表示拡大率、先行バッファ深度、音声ビットレート、サーバー映像パフォーマンスプリセット、クライアント負荷プロファイル）はネイティブ `<select>` を使用しない（Chrome ネイティブのポップアップは車載タッチでは即閉じとなり操作不能）。タップ 1 回で十分なタップ領域の選択肢一覧をアプリ内ピッカーとして開き、選択確定・背景タップ閉じが 1 タップで完結する統一コントロールへ置き換える。選択肢の段階・既定値・選択肢外値のフォールバック・保存経路（`PUT /api/settings`）は以下の現行規定と同一とする。
  - 新しい PIN コード（空欄で維持、4〜8 桁半角数字検証）。
  - **ブラウザ表示拡大率（PR #102 / Issue #101 統合）**: 選択肢を 10% 刻み 8 段階（**`60%〜130%`、既定 `100%`**、`140%`/`150%` 廃止）とする。**無効な値および選択肢に存在しない保存値を受け取った場合は、動的「(現在の保存値)」オプションは生成せず既定の `100%` へフォールバック** する。
  - 先行バッファ深度（`0 / 2,000 / 5,000 / 10,000 [既定] / 20,000 / 30,000 ms`、サーバー保存値から取得）。
  - 音声ビットレート（`128k [既定] / 192k / 256k / 320k`、サーバー保存値から取得）。
  - **パラメータ設定 UI 再設計対象（クライアント負荷プロファイル & サーバー映像パフォーマンス）**:
    - サーバー映像パフォーマンスプリセット（5 秒間隔ヘルスチェック取得でバックエンド種別・エンコード寸法縮小表記・ソフトウェア時警告バナーを表示、NVENC/CPU 時の無効化理由を正確に表示、非互換保存プリセットの表示上 `custom` 展開・詳細編集時 `custom` 切替、名称の明確化）。
    - クライアント負荷プロファイル（`standard` / `lightweight` / `custom` — 実効スケール・許容 FPS・連動ビットレートのプレビュー整合性を担保し、UI とサーバー設定定義の乖離をなくす）。
  - *非表示項目*: システム表示言語（既定 `ja-JP`、環境変数のみ）・タイムゾーン・`autoSleepMinutes`・`x264Preset`・`custom.bitrateDefault` は UI に露出せず、集約されたサーバー規定値のみを使用する。
- **タブ 3 — 品質メトリクス**: 3 秒周期でサーバー集計サマリを表示。詳細テレメトリ収集トグル（既定 OFF、サーバー設定保存）とサーバーログ全消去ボタン（**5 秒以内の 2 タップ確認**）を備える。
- オンボーディングガイド内の HUD 説明表記は現行仕様（`24 / 30 / 60 FPS`・`0.25M〜2.0M`）へ整合する。

## 3. 非機能要件・制約条件

- **小窓表示主対象（Primary Target: Small Window）**:
  - 実車利用ではナビ等と並べる小窓表示が中心となるため、UI 視認性・操作性およびエンコード解像度は小窓（代表基準 `773×553 CSS / DPR 1.53`）を主対象として最適化する（全画面表示時にも破綻なく追従させる）。
- **DPR 値の非ハードコード**:
  - 将来の車載ファームウェア更新で DPR が変化し得るため、`1.53` などの特定 DPR 値を UI・CSS・計算ロジックへ固定値として直書きしてはならない。実行時の物理ピクセル（`devicePixelRatio` ベース）およびサーバー側リサイズ計算（[03-streaming-transport.md](03-streaming-transport.md) §2.1 / [05-encoder-gpu.md](05-encoder-gpu.md) §2.3）で動的に吸収する。
- **完全タッチオンリー環境厳守**:
  - 車載ディスプレイは完全タッチ操作のため、`Escape` キーでのモーダル閉じ・キーボードショートカット・`keydown` 依存・`hover` のみで露出する UI・右クリックメニュー・マウスポインタ前提ドラッグを実装してはならない。
  - ネイティブダイアログ（`window.prompt()`, `window.confirm()`）は完全に禁止し、アプリ内モーダルへ統一する。
  - ネイティブフォームポップアップ（`<select>` ドロップダウン、日付・時刻ピッカー等）はブラウザネイティブ UI 依存で車載タッチ操作が及ばないため禁止し、すべての選択操作はアプリ内のタッチ専用カスタムピッカーへ統一する。
- **ステートレスな車載ブラウザ**: 車両ブラウザ側の `localStorage` に永続設定を持たせず、別の車載ブラウザや端末交代時もサーバー接続のみで同一設定を復元できること。
- **XSS 防止**: お気に入りタイトル・URL などユーザー入力由来の文字列は描画時に必ず無害化する。

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **YouTube ドメイン偽装 URL**: `https://youtube.com.evil.example/watch` 等は正規表現およびホスト一致検証で確実に YouTube 対象外と判定し検索バーを隠す。
2. **カスタム順序のお気に入り保持**: ユーザーが「ホーム」を先頭（index 0）以外へ移動した設定ファイル読み込み時や、新規追加・他項目削除時に、勝手にホームを先頭へ戻さずユーザーの並び順を維持する。
3. **非同期取得の順序競合**: 設定モーダル初期化時に設定取得 API がヘルスチェック API より先に完了した場合でも、後着のバックエンド情報を用いて正しいプリセット表示へ追従・復元する。
4. **表示拡大率の選択肢外値・無効値**: `140%`/`150%`・`NaN`・空白・`null` 等がいかなる経路で渡されても、不正な選択肢を作らず `100%` へ安全にフォールバックする。
5. **設定保存 API 失敗時**: サーバー更新失敗時はクライアント上の表示・一時状態を書き換えずエラーを通知し、サーバー・クライアント間の不整合を起こさない。
6. **ファームウェア更新による DPR 変動・小窓↔全画面切替**: 車載 OS 更新等で DPR が `1.53` 以外の値へ変化した場合や小窓・全画面を切り替えた場合も、ハードコードされた DPR 仮定に依存せず、実行時の物理ピクセル計測とサーバー側リサイズ計算によりレイアウトと描画アスペクト比を破綻なく維持する。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (車載 HUD レイアウトと必須要素・不要要素排除)**:
  - **Given** ストリーミング画面および設定コンソール（小窓 `773×553 CSS` 基準および全画面）
  - **When** DOM 構造と各画面ボタン・設定項目・DPR 依存コードを検査する
  - **Then** HUD は映像ビューポートより上部に配置されて小窓表示でも左切れ防止の中央揃えと十分な視認性が保たれ、特定 DPR（`1.53` 等）の固定値直書きが存在せず、旧不要ボタン・言語変更欄・設定画面内の電源/再エンコード/音声テスト/ログ DL ボタン、および `<video>` タグや `localStorage` 設定読み書きコードは存在しない。
- **AC-02 (ドロワー相互排他・YouTube 検索バー・連打ガード・上限 2.0M)**:
  - **Given** 稼働中の HUD 画面
  - **When** 両ドロワーの交互開閉、YouTube 正規/偽装 URL 切替、LIVE ボタン連打、ビットレート循環を行う
  - **Then** 両ドロワーは排他開閉し、YouTube 正規ドメイン時のみ検索バーが表示され、LIVE ボタン連打時も 1 秒ガードが働き、ビットレート循環は `0.25M〜2.0M` でサーバー上限と完全一致する。
- **AC-03 (お気に入り管理・重複 URL 拒否・XSS 無害化)**:
  - **Given** お気に入り管理 UI および設定 API
  - **When** 重複 URL・不正 URL・100 件超過・HTML スクリプトを含むお気に入り操作および 2 タップ初期化を行う
  - **Then** 同一 URL 重複登録は現在ページ追加・手動追加・編集・API のすべてで拒否され、不正 URL/100 件超過も拒否され、XSS ペイロードは無害化され、設定更新イベントで HUD へ即時反映される。
- **AC-04 (表示拡大率 `60〜130%` 既定 `100%` とフォールバック — PR #102 統合)**:
  - **Given** 設定画面の表示拡大率タッチ専用ピッカー
  - **When** 選択肢一覧を確認する／`150%`・`NaN`・空白などの無効・選択肢外値を読み込む／`60%` を選択保存する
  - **Then** 選択肢は `60〜130%` の 8 段階で既定 `100%` となり、無効・選択肢外値は動的オプションを作らず `100%` へフォールバックし、`60%` 選択時に `displayScale: 60` がサーバーへ保存される。
- **AC-05 (アプリ内タッチ専用モーダル統一 & 省電力モーダル)**:
  - **Given** 未認証での設定アイコン押下および省電力モーダルからのブラウザ再起動・停止・切断
  - **When** 各操作を実行する
  - **Then** `window.prompt()` / `window.confirm()` は一切呼ばれずアプリ内タッチモーダルで完結し、省電力操作は単一電源管理ドメイン API を呼び出す。
- **AC-06 (選択肢コントロールのタッチ専用ピッカー統一)**:
  - **Given** 設定モーダル タブ 2（表示拡大率・先行バッファ深度・音声ビットレート・サーバー映像パフォーマンスプリセット・クライアント負荷プロファイル）
  - **When** 各選択肢コントロールをタップする
  - **Then** ネイティブ `<select>` 要素およびブラウザネイティブのポップアップはソース・ビルド成果物に存在せず、車載相当タッチ操作での即閉じが発生せず、十分なタップ領域のアプリ内ピッカーが開く。
  - **When** ピッカーの選択肢一覧で項目をタップする
  - **Then** その項目が即時確定し、既存の `PUT /api/settings` 検証・段階規定どおりにサーバーへ保存され、ピッカーが閉じる。
  - **When** ピッカーの背景（一覧外）をタップする
  - **Then** 値を一切変更せず、ピッカーのみが閉じる。
