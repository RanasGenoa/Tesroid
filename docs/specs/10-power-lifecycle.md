# 仕様書 10: 電源・スリープ・ライフサイクル管理

> ※ 本ドメインは、従来「仮想ブラウザ管理」「ストリーミング転送」「設定/ブラウザ API」に分散していた電源・スリープ・Buffer-Hold 凍結・再起動の状態管理を単一ドメインへ集約し、状態不整合を根絶するために新設されたドメインである。

## 1. 概要と目的

クラウドブラウザおよびメディアエンコーダの起動・稼働・Buffer-Hold 一時凍結・省電力スリープ・再起動・停止のライフサイクルを一つの状態機械および外部制御インターフェースで一元管理し、降車時の CPU/GPU 負荷ゼロ化、狭帯域時の一時生成停止、操作・接続復帰時の確実な両プロセス再開（片肺無音やタイマー競合の排除）を保証する。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 単一ライフサイクル状態機械
システム全体の稼働状態を以下の排他的な単一状態として管理する。

- **`STOPPED`**: 仮想ブラウザおよびエンコーダが未起動または完全停止している初期/終了状態。
- **`STARTING`**: 仮想ディスプレイ・仮想オーディオ・ブラウザ・エンコーダを起動している遷移中状態。
- **`ACTIVE`**: ブラウザおよび映像・音声エンコーダがともに稼働し、通常配信が可能な状態。
- **`BUFFER_HOLD`**: クライアント未接続時および極端な滞留時のリングバッファ溢れ・送出漏れを防止するため、`SessionRegistry` が保持する現世代プライマリ確認済み PTS（音声実再生地点）基準の未消費占有率 `>= 85%` 到達でブラウザを凍結（`SIGSTOP`）・エンコーダを一時停止してサーバー生成を `0.0x` に落としている状態。生成停止のみを意味し、再接続したクライアントへの既生成バッファ送出（CATCHUP 排水）は継続して確認済み PTS 基準の未消費占有率 `<= 10%` で `ACTIVE` へ自動復帰する。ユーザー向け電源表示としては稼働中扱い（HUD に `HOLD` 表示）を維持し、自動スリープとは異なる有効期限タイマーで管理される。
- **`SLEEP_PAUSED`**: 一定時間のクライアント不在またはユーザーの手動停止により、エンコーダ停止・ブラウザ凍結（`SIGSTOP`）・リングバッファ消去を行って CPU/GPU 負荷を 0% に落としている省電力状態。
- **`RESTARTING`**: ブラウザまたは全パイプラインのクリーン再起動を実行中の遷移状態。
- **`ERROR`**: 起動不能または復旧不能な異常状態。

### 2.2 統一された外部インターフェース（REST / WebSocket）
従来の重複していたブラウザ制御・システム電源制御の複数 API を廃止し、以下の単一インターフェースへ統一する（すべて Bearer トークン認証またはプライマリ相当 WS 権限を必須とし、後席スタンバイ中および非代理セカンダリからの電源停止・再起動要求は拒否する）。

- **`GET /api/power/status`**（公開状態取得に統合可）: 現在の統一ライフサイクル状態（`ACTIVE`, `BUFFER_HOLD`, `SLEEP_PAUSED` 等）およびブラウザ現在ページ情報を返却する。
- **`POST /api/power/sleep`**（および対応 WS コマンド `PAUSE_BROWSER`）: 状態に関わらず共通のスリープ遷移を実行する。`BUFFER_HOLD` 中に呼ばれた場合も再開チャーンを経由せず直接 `SLEEP_PAUSED` へ変換する。
- **`POST /api/power/resume`**（および対応 WS コマンド `RESUME_BROWSER`）: `SLEEP_PAUSED` からブラウザを復帰（`SIGCONT`）させ、**映像・音声双方のエンコーダが確実に稼働した状態** で `ACTIVE` へ戻し、新 `streamEpoch` を発行して全接続クライアントへ状態通知する。
- **`POST /api/power/restart-browser`**（および対応 WS コマンド `RESTART_BROWSER`）: 進行中の追っかけキューや Hold 状態をすべて解除し、リングバッファをクリアしてブラウザを再起動した上で、映像・音声双方のエンコーダ稼働を保証して `ACTIVE` へ戻す。
- ※ 配信のみのクリーンリセットは [03-streaming-transport.md](file:///Users/takumi/Desktop/Tesroid/docs/specs/03-streaming-transport.md) の `POST /api/stream/reset` と連携し、Hold 中に呼ばれた場合は Hold を解除して新 `streamEpoch` で再配信を開始する。

### 2.3 ドメイン間内部インターフェース契約
本ドメインは他ドメインの責務を直接記述せず、以下の境界契約を通じて協調する。

- **対 仮想ブラウザドメイン ([06-browser-input-cdp.md](file:///Users/takumi/Desktop/Tesroid/docs/specs/06-browser-input-cdp.md))**: プロセスツリー凍結（`SIGSTOP`）、復帰（`SIGCONT`）、再起動、ページ監視の一時停止/再開を指示する。
- **対 エンコーダドメイン ([05-encoder-gpu.md](file:///Users/takumi/Desktop/Tesroid/docs/specs/05-encoder-gpu.md))**: 映像・音声エンコーダの停止、双方の稼働保証付き起動（片肺防止：`video && audio` 両稼働を必須条件とする）、タイムライン補償の記録/リセットおよび新 `streamEpoch` の発行を指示する。
- **対 ストリーミング転送ドメイン ([03-streaming-transport.md](file:///Users/takumi/Desktop/Tesroid/docs/specs/03-streaming-transport.md))**: 電源 FSM とストリーミング状態機械は互いの boolean フラグを直接読み書きせず、電源ドメインがストリーミング側の単一遷移関数へ明示イベント（`ENTER_BUFFER_HOLD`, `EXIT_BUFFER_HOLD`, `POWER_SLEEP`, `SESSION_ACTIVATED` 等）を投入して状態同期し、ストリーミング側からの宣言的 Hold/再開要求を受けて電源状態遷移およびクライアントへの `BUFFER_HOLD` / `BROWSER_STATUS` 通知を実行する。
- **対 セッション管理ドメイン ([02-session-multidisplay.md](file:///Users/takumi/Desktop/Tesroid/docs/specs/02-session-multidisplay.md))**: プライマリ接続・代理昇格・全プライマリ離脱・再接続のイベントを受信し、スリープ解除またはタイマー武装を実行する。`SLEEP_PAUSED` 遷移時に視聴中セカンダリを待機状態（`SECONDARY_STANDBY`）へ移行させ、また `streamEpoch` 更新およびスリープ移行時には `SessionRegistry` のプライマリ確認済み PTS 基準点を即座に未受信（`null`）へリセットする。

### 2.4 タイマー排他と自動スリープ／Buffer-Hold 期限仕様
- **タイマー厳格排他**: 自動スリープタイマー（`autoSleepTimer`）と Buffer-Hold 有効期限タイマー（`holdExpireTimer`）は **同時に 2 つ以上稼働させてはならない**。
- **自動スリープ発動条件**:
  - プライマリおよび代理プライマリが不在となった時点で武装する（設定 `autoSleepMinutes` 既定 `3 分`、遅延 `max(15_000, autoSleepMinutes * 60_000)` ms、`0` 設定時は自動スリープ無効）。
  - 猶予内にプライマリ（または有効な代理プライマリ）が接続した場合は即座にキャンセルする。
- **`BUFFER_HOLD` 中のプライマリ切断と期限タイマー再武装（`autoSleepMinutes = 0` 含む）**:
  - `BUFFER_HOLD` 突入時に `autoSleepTimer` を停止し、Hold 有効期限タイマー（`BUFFER_HOLD_EXPIRE_MINUTES` 既定 `10 分`、最小 `1 分`）を武装する。
  - **不変条件**: **`autoSleepMinutes = 0`（自動スリープ無効）が設定されている環境であっても、`BUFFER_HOLD` 中にプライマリが切断（または再切断）した場合は、必ず `holdExpireTimer` を再武装** し、ブラウザが永久に凍結状態のまま放置されることを防ぐ。セカンダリのみの接続・再接続では `holdExpireTimer` を解除しない。
  - `holdExpireTimer` 満了時は共通のスリープ遷移フローへ合流し、`SLEEP_PAUSED` へ移行してリングバッファ消去・時間補償値リセット・セカンダリ待機化を行う。

## 3. 非機能要件・制約条件

- **単一状態機械原則**: REST API と WebSocket 経路のどちらから電源操作が来ても、必ず本ドメインの単一状態機械を経由させ、状態遷移とクライアント通知の乖離を起こさない。
- **片肺無音防止（完全稼働不変条件）**: `ACTIVE` 状態への復帰・再開経路では、常に「映像エンコーダと音声エンコーダの双方が稼働していること」を検証・保証する。
- **省電力実効性**: `SLEEP_PAUSED` および `BUFFER_HOLD` 中はエンコーダ停止とブラウザプロセスツリー凍結によりサーバー CPU/GPU 使用率をほぼ 0% へ抑える。

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **Buffer-Hold 中のプライマリ接続（奪取 4009 vs 同一セッション再接続）**: 別プライマリが PIN ログイン等でセッションを奪取（`4009`）してきた場合や操作・リセット時は、未消費バッファを破棄して即座に Hold を解除し映像・音声双方を起動して `ACTIVE` へ復帰する。一方、同一プライマリの再接続で CATCHUP 排水が可能な場合は `BUFFER_HOLD`（生成停止）を維持したまま既生成バッファを送出し、未消費占有率 `<= 10%` への排水完了で `ACTIVE` へ自動復帰する。
2. **Buffer-Hold 中に追っかけ不能（`LIVE` 転落）となった再接続**: Hold 状態を維持したまま `LIVE` になると画面が凍結したままとなるため、即座に Hold を解除して `ACTIVE` へ復帰する。
3. **Hold 中の電源停止（スリープ）要求と非同期再起動の競合**: Hold 解除処理とスリープ停止が競合して停止直後にエンコーダが再起動する事故を防ぐため、Hold 中の停止要求は Hold 再開処理を行わず直接 `SLEEP_PAUSED` へ変換する。
4. **スリープ状態での状態取得・再起動後の復旧**: スリープ中に明示的なブラウザ再起動が指示された場合は、凍結解除・再起動後にエンコーダ双方を起動して `ACTIVE` へ復帰する。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (単一電源制御 API による状態一貫性)**:
  - **Given** `ACTIVE` または `BUFFER_HOLD` 状態で稼働中のサーバー
  - **When** REST（`POST /api/power/sleep`）または WS（`PAUSE_BROWSER`）から停止を実行し、続いて復帰（`POST /api/power/resume`）または再起動（`POST /api/power/restart-browser`）を実行する
  - **Then** どちらの経路でも同一の状態機械（`SLEEP_PAUSED` → `ACTIVE`）が実行され、Hold 補償リセット・リングバッファ消去・映像/音声両稼働・クライアントへの `BROWSER_STATUS` 通知が一貫して行われる。
- **AC-02 (タイマー排他 & `autoSleepMinutes = 0` 下の Hold 期限保証)**:
  - **Given** `autoSleepMinutes = 0` に設定され、`BUFFER_HOLD` 状態にあるシステム
  - **When** プライマリが切断し、その後 `BUFFER_HOLD_EXPIRE_MINUTES`（既定 10 分）が経過する
  - **Then** `autoSleepTimer` は稼働しないが `holdExpireTimer` が確実に再武装され、期限到達時に共通スリープフローへ合流して `SLEEP_PAUSED` へ遷移し永久凍結を防ぐ。
- **AC-03 (Hold 中の手動停止・4009 奪取・操作/リセット・`LIVE` 転落時の安全遷移)**:
  - **Given** `BUFFER_HOLD` 中（未消費占有率 `>= 85%`）で `CATCHUP` または待機状態にあるセッション
  - **When** 手動停止を実行する／別プライマリがセッション奪取（`4009`）する／同一プライマリ再接続が追っかけ不能で `LIVE` に遷移する／操作・リセットを行う
  - **Then** 手動停止時はエンコーダ再起動チャーン無しで即 `SLEEP_PAUSED` へ変換され、4009 奪取・`LIVE` 転落・操作・リセット時は未消費バッファを破棄して確実に Hold が解除され映像・音声双方が起動する（同一プライマリの CATCHUP 排水時は `<= 10%` まで生成停止を維持したまま送出を継続する）。
- **AC-04 (自動スリープ発動と猶予内キャンセル)**:
  - **Given** `autoSleepMinutes = 3` で `ACTIVE` 状態のシステム
  - **When** プライマリおよび代理プライマリが不在となり、猶予内に再接続する場合と猶予を超過する場合
  - **Then** 猶予内再接続時はスリープがキャンセルされて配信が継続し、猶予超過時は `SLEEP_PAUSED` へ遷移して視聴中セカンダリが待機状態へ移る。
