# 仕様書 06: 仮想ブラウザ・入力注入・電源管理

## 1. 概要と目的

Docker コンテナ内の仮想ディスプレイ上で安定したハードウェア支援 Google Chrome と仮想オーディオ環境を稼働させ、テスラ車載ディスプレイからの直感的なネイティブタッチ操作・ソフトウェアキーボード文字入力・Web フルスクリーン視聴・操作不能な Chrome ネイティブ UI の抑止を提供する（電源・スリープ・再起動のライフサイクル状態管理および外部 API は単一ドメイン [10-power-lifecycle.md](10-power-lifecycle.md) に集約して制御する）。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 仮想ディスプレイ・音声・ブラウザハイブリッド描画スタック
- **仮想オーディオ環境**:
  - 専用設定ファイル（`/etc/pulse/tesroid.pa`）を明示指定して PulseAudio を起動し、UNIX ドメインソケット（`/tmp/pulse-socket`、匿名許可）および仮想シンク（`48000Hz / stereo / s16le`、音量 `100%`・ミュート解除は `.pa` スクリプトのみで保証する）を生成する（起動待ち上限 `3,000 ms`）。flat-volume 切替は PulseAudio `14` 以降で削除済みのため、対応 CLI オプション（`--flat-volumes` 等）は起動引数に含めない。
  - **起動前・起動後の自己修復**: 起動前に stale なソケットファイルと既存デーモン（`pulseaudio -k`）を掃除する。起動後に仮想シンクが欠落している場合は `pactl load-module` で再ロードし、既定シンク設定・音量 `100%`・ミュート解除を強制する。この自己修復を試みた後も応答しない場合のみ起動失敗とする（fail-fast は自己修復の後に適用する）。
- **仮想ディスプレイ & ウィンドウマネージャ**:
  - 仮想 X11 ディスプレイ（`>= 1920×1080 × 24bit`、GLX/RANDR/RENDER 有効、リセット抑止）と、すべてのウィンドウを枠なし・座標 `(0, 0)` 固定・最大化/OS フルスクリーン無効化する軽量ウィンドウマネージャ（Openbox）を起動する。
- **Google Chrome ハイブリッド描画起動**:
  - 永続データディレクトリ内のプロファイル配下 `Singleton*` を**ワイルドカードで全除去**し、クラッシュ状態（`exit_type` 等）を**トップレベル `Preferences` と `Default/Preferences` の両方**について正常値へ修復した上でスタンドアロンアプリモード（`--app=<url>`）で起動する。
  - **ブラウザバイナリ実行時検出**: `google-chrome-stable` → `google-chrome` → `chromium-browser` → `chromium` の順に実行可能な最初のものを選択し、固定シンボルリンク名に依存しない。
  - **起動時初期 URL**: 環境変数 `BROWSER_URL` は廃止し、常にサーバー設定のお気に入り「ホーム」URL（未設定時は `https://www.youtube.com`）から解決する。
  - **役割分離（デッドロック回避・レンダノード固定）**: 動画デコードのみ VAAPI ハードウェアデコードを有効化し、エンコーダドメインの検出結果から解決したレンダリングノードを `--render-node-override` で明示指定した上で GPU ブロックリストを解除する（llvmpipe 系の仮想 GPU 構成では Chrome のブロックリストがハードウェアデコード判定自体を無効化するため、解除なしでは Video Decode が Software only に留まる）。AV1 ソフトウェアデコードは無効化し H.264/VP9 へ誘導する。さらに単一ページスクリプト注入により、**GPU のデコード能力の有無にかかわらず**ページ側のコーデック選択は VP9/AV1 を選ばず常に H.264 を選択する（互換性優先: H.264 はハードウェアデコード非対応環境でもソフトウェアデコードで成立する唯一のユニバーサルコーデックであり、VP9 高ビット深度配信時のソフトウェアデコードによるレンダラ CPU飽和を構造的に起こさない。実測: 非対応環境での VP9 10bit 配信時にレンダラ CPU 100%）。
  - **言語・タイムゾーン・音声シンク**: 環境変数 `LOCALE`（既定 `ja-JP`）および設定タイムゾーン（既定 `Asia/Tokyo`）をプロセス環境およびブラウザ設定へ反映する。`--lang` に加え、`LOCALE` から導出する Accept-Language 順序リスト（既定は `ja-JP,ja,en-US,en`）を起動引数 `--accept-lang` と Preferences（`intl.accept_languages` / `selected_languages`）の両方で明示する。ブラウザプロセス環境には `PULSE_SERVER`（UNIX ソケット）に加え `PULSE_SINK`（仮想シンク名）を設定し、既定シンクへの暗黙依存を排除する。
  - **VAAPI ドライバ名の明示伝播**: VAAPI デコードのドライバ名はエンコーダドメインの検出結果をブラウザプロセス環境の `LIBVA_DRIVER_NAME` でのみ明示伝播する（`--render-node-override` と同一検出源）。Chrome の libva 自動探索に委ねず、検出 null では既定値を注入しない（仕様 09 §2.4）。三点セット以外の GPU 強制フラグ（`--enable-accelerated-video-decode`、`--disable-dev-shm-usage` 等）は Xvfb 構成で Video Decode を Software only へ退行させるため付与しない。
  - **車載表示・タッチ能力・耐障害フラグ**: 起動引数に `--touch-events=enabled`（タッチ能力検出で UI を切り替えるサイトがあるため Blink のタッチ機能を有効化）、`--force-dark-mode`（車載眩低減のためダークテーマを Cookie に加え恒久化）、`--disable-gpu-sandbox`（GPU プロセスの `/dev/dri` アクセス担保）、`--hide-crash-restore-bubble`（クラッシュ状態修復と併用する復元バブル抑止の二重保証）を常に含める。
  - **異常終了回復 & 安全性**: Chrome が予期せず終了した場合は `2,000 ms` 後（起動直後 1 秒以内終了時もリトライ）に自動再起動する。ナビゲーション URL は `http:` および `https:` スキームのみ厳格に許可する。

### 2.2 ネイティブタッチ入力 & OSK 文字・キー注入
- **クライアント側前処理 & 座標変換**:
  - 画面上端 **20 px 以内** のタッチ開始は車載 OS ブラウザの上端スワイプ終了ジェスチャー保護のため抑止する。
  - `6 px` のタッチスロップ、`60 ms / 20 px` の接点チャタリングデバウンス、非プライマリボタン無視、ウィンドウフォーカス喪失・キャプチャ喪失時の全タッチキャンセルを適用し、`object-fit: contain` のレターボックス/ピラーボックス余白を除外したキャンバス相対座標へ変換する。
  - タッチ座標は**有効レイアウト寸法**（共有 `alignLayoutDimensions` を当前の `stream.maxSize` に適用した結果）空間で正規化し、フレームの `screenWidth` / `screenHeight` もこの有効寸法を保持する。クライアントは同一関数をローカルで適用して同一値を算出するため、サーバーは CDP へそのまま注入する（変換なし・同一関数による構成的一致）。`maxSize` 設定変更時は次のリサイズ報告を待たず再計算・反映する（[05-encoder-gpu.md](05-encoder-gpu.md) §2.3 の即反映規定と整合）。
  - マルチタッチアクション（`DOWN=0, UP=1, MOVE=2, CANCEL=3, POINTER_DOWN=5, POINTER_UP=6`）を送出する。
- **サーバー側 CDP タッチ注入**:
  - Chrome DevTools Protocol（CDP）接続（`127.0.0.1:9222`、切断時は `2,000 ms` 周期で自動再接続）専用の単一経路とし、Blink エンジンへネイティブタッチイベント（`touchStart / touchMove / touchEnd / touchCancel`）を直接注入することで慣性スクロールおよび誤ドラッグ防止を実現する。
  - サーバー側でも `8 px` スロップ、`80 ms / 15 px` デバウンス（デバウンス中に `8 px` 超ドラッグしたら即時 `touchStart` へ昇格）、`2,500 ms` 無応答タッチの自動キャンセル、新規 `DOWN` 時の残留タッチ自動リセットを行う。
  - CDP 未接続・切断時のタッチイベントは X11（`xdotool`）等へフォールバックせず安全に破棄（ログ記録可）し、進行中タッチのローカル状態をリセットした上で `2,000 ms` 周期の CDP 自動再接続を待つ。
- **文字・特殊キー・ナビゲーション注入**:
  - クライアントの編集可能入力欄経由で送信された文字列は、検索欄への自動フォーカス等に依存しないシンプルな CDP テキスト注入で直接入力する。
  - 特殊キー（`Enter`, `Backspace`, `Tab`, `Escape`, `Space`, `Delete`, 方向キー）および戻る・進む・再読み込み・フルスクリーン切替も CDP 経由のみで実行する。CDP 未接続・切断時はフォールバックせず安全に破棄（ログ記録可）し、再接続後に再び注入を受け付ける（非 `http:`/`https:` URL の `navigate` 要求は接続状態に関わらず即時拒否する）。

### 2.3 Chrome ネイティブ UI（Views Bubble・infobar）抑止
- **WebAuthn / パスキー抑止**:
  - プラットフォーム認証器・条件付きメディエーション利用可否を常に `false` とし、`publicKey` オプション付きのクレデンシャル取得・作成要求をネイティブダイアログ起動前に `NotAllowedError` で即座に拒絶する（非パスキー要求は元メソッドへ透過）。
- **パスワード保存・自動入力・翻訳バブル抑止**:
  - ブラウザ設定ファイルおよび起動引数により、翻訳機能・パスワード保存/漏洩検知・自動サインイン・住所/カード自動入力バブルおよび OS キーリングプロンプトを恒久抑止する（既存の正常終了フラグは保持）。
- **コマンドラインフラグ警告 infobar 抑止**:
  - `--no-sandbox`（コンテナ root 稼働で必須）により Chrome が「サポートされていないコマンドラインフラグ」のネイティブ infobar を表示する。これは現行 Chrome で `--disable-infobars` が廃止済みで起動引数では抑止できず、車載タッチオンリーでは閉じる操作もできないため、managed policy（`/etc/opt/chrome/policies/managed/` に `CommandLineFlagSecurityWarningsEnabled: false`）をイメージへ焼き込んで恒久抑止する。

### 2.4 車載表示拡大・Web フルスクリーン・スクリプト集約 & ページ監視
- **スクリプト注入元の単一集約**: WebAuthn 抑止・車載表示拡大・Web フルスクリーン・動画音声維持のスクリプト注入および設定反映は単一の制御箇所へ集約し、多重定義や拡大率フォールバック値の食い違いを防ぐ。
- **表示拡大ズーム**: 許容範囲 `50%〜250%`・**既定値 `100%`**（範囲外・無効値は `100%` へフォールバック）をページ全体に適用し、Web フルスクリーン再生中も `100%` を維持する。REST API および WebSocket `SET_ZOOM` の双方で `[50, 250]` クランプと有限数値検証を一貫適用する。
- **仮想 Web フルスクリーン**: DOM Fullscreen API をインターセプトし、OS フルスクリーンへ遷移させずビューポート全面（`100vw × 100vh`・最前面・アスペクト比維持）へ拡大する。YouTube の画面サイズ判定（2 秒後のフルスクリーンボタン無効化）をウィンドウ寸法応答で回避し、ダークテーマ/シアターモード Cookie 付与を行う。YouTube プレイヤーではフルスクリーンボタンの操作維持（`disabled` / `aria-disabled` 除去・`pointer-events` 強制・capture 位相でのボタンタップ遮断）、プレイヤー内部 `toggleFullscreen` の仮想フルスクリーンへの接続、SPA 遷移（`yt-navigate-start`）時の仮想フルスクリーン自動解除を適用し、動画領域以外の装飾（ヘッダー、サイドバー、コメント欄、ガイド、cinematics 効果、プレイヤー背景）を非表示化する。非 YouTube の一般動画要素およびコンテナ要素も同様に全画面化する。
- **動画サイト側音量の常時最大維持**: 車載側の音量コントロールに一本化するため、コンテナ内ブラウザの動画プレイヤーは 2 秒周期の監視等により **常にミュート解除・音量 100% 固定** を維持する（動画サイト側での音量操作をさせない想定）。
- **リアルタイムページ監視**: CDP イベントによる即時同期（`Page.frameNavigated` / `navigatedWithinDocument`（発火 400 ms 後にタイトル再取得）/ `loadEventFired` / `Page.domContentEventFired` で直ちに URL・タイトルを評価）を主経路とし、3 秒間隔の状態確認をフォールバックとして、現在 URL（`http:`/`https:` のみ）とタイトルを同期し、クライアントへ通知する（スリープ・Buffer-Hold 凍結時は監視を停止する）。

### 2.5 電源・ライフサイクル管理ドメインとの連携（プロセス操作責務）
- 電源状態の遷移、タイマー排他、REST/WS 外部制御窓口はすべて **[10-power-lifecycle.md](10-power-lifecycle.md)** の単一ドメインへ集約し、本ドメインは以下のプリミティブ操作のみを単一ドメインからの指示で実行する:
  - ブラウザプロセスツリーの凍結（`SIGSTOP`：子孫→親のボトムアップ順）および再開（`SIGCONT`：親→子のトップダウン順、存在しない PID は無視）。
  - ブラウザの再起動および起動/停止状態の報告。

## 3. 非機能要件・制約条件

- **コンポジタデッドロック禁止フラグ**: Xvfb 環境の Chrome に対し、`--enable-gpu-rasterization`・`--enable-zero-copy`・`--disable-gpu-vsync` を絶対に付与しないこと。
- **CDP ネイティブ入力専用原則**: 常設入力をマウスエミュレーションや X11 入力フォールバックへ戻さず、常に CDP 経由のみで注入すること。
- **ネイティブ UI 抑止の維持**: 車載 DOM タッチで閉じられないパスキー・パスワード保存・翻訳等のネイティブダイアログを絶対に出現させないこと。
- **OSK 入力制約**: 映像キャンバス直接タップでは車載ソフトウェアキーボードが開かないため、常に編集可能 DOM 入力欄を介した文字注入経路を維持すること。

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **不正または `<= 0` の画面サイズに対するタッチ入力**: 例外やゼロ除算を起こさず安全に無視する。
2. **非 HTTP/HTTPS URL への遷移要求**: `file://`, `chrome://`, `javascript:` 等は入力検証で即時拒否し遷移させない。
3. **プロセス親子関係の循環異常**: プロセス一覧取得時の PPID 循環に対しても無限ループせず安全に走査を打ち切る。また Linux の 15 文字実行名切り詰めに対応する。
4. **動画要素が存在しないページでのフルスクリーン操作**: エラーを出さず安全に無処理（no-op）とする。
5. **非同期タイマー残存による凍結中タイムアウト**: ブラウザ凍結中に CDP 評価ポーリングを実行してタイムアウトエラーを量産しないよう、凍結時は監視タイマーを停止する。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (ハイブリッド描画・初期ホーム URL・PulseAudio 不変条件)**:
  - **Given** お気に入りホーム URL が設定された仮想ブラウザ起動環境
  - **When** 起動引数を生成し、環境を初期化する
  - **Then** `--enable-gpu-rasterization` や `--enable-zero-copy` が含まれず、`--app=<お気に入りホームURL>`、`LOCALE` 既定 `ja-JP` と一致する `--accept-lang` / Preferences `intl.accept_languages`、基本パスワードストア、VAAPI 動画デコード（`--render-node-override=<検出ノード>` および `--ignore-gpu-blocklist` の適用により chrome://gpu の Video Decode が Hardware accelerated であること）、専用 PulseAudio UNIX ソケット設定と `PULSE_SINK` 明示が確実に適用され、PulseAudio 起動引数はイメージ稼働バージョンで受理されない削除済みオプション（`--flat-volumes` 等）を含まない。またブラウザプロセス環境は VAAPI 検出と同一のドライバ名を `LIBVA_DRIVER_NAME` として含み（検出 null では注入しない）、三点セット外の GPU 強制フラグ（`--enable-accelerated-video-decode`、`--disable-dev-shm-usage` 等）を含まない。
  - **And** 起動引数に `--touch-events=enabled`・`--force-dark-mode`・`--disable-gpu-sandbox`・`--hide-crash-restore-bubble` が含まれ、ブラウザバイナリは 4 候補（`google-chrome-stable` / `google-chrome` / `chromium-browser` / `chromium`）から実行時検出される。
  - **And** 単一ページスクリプト注入は GPU 能力にかかわらず常に有効であり、`MediaSource.isTypeSupported` 上で vp9/av1 を拒否し h264 のみ受理するため、ページ側プレイヤーは常に H.264 配信を選択する。
- **AC-02 (タッチ座標変換・上端ガード・CDP 注入と切断時安全破棄)**:
  - **Given** 映像キャンバス上のタッチ操作および CDP 接続/切断状態
  - **When** 上端 20px 以内へのタッチ、8px 以上のドラッグ、マルチタッチ、2.5 秒以上のスタックタッチ、および CDP 未接続・切断時のタッチ／文字／キー／ナビゲーション入力をテストする
  - **Then** 上端 20px 以内は無視され、有効タッチは余白補正の上で CDP 注入（デバウンス・スロップ・自動キャンセル・残留リセット適用）され、CDP 未接続・切断時の入力はフォールバックやクラッシュを起こさず安全に破棄され、再接続後に正常注入へ復帰する。
- **AC-03 (WebAuthn & パスワードバブル抑止)**:
  - **Given** 単一制御元からスクリプトが注入されたブラウザページ（`<all_urls>`）
  - **When** プラットフォーム認証器確認および `publicKey` 指定の有無それぞれで `credentials.get/create` を呼び出し、また設定ファイルを書き込む
  - **Then** 認証器利用可否は `false`、パスキー要求は `NotAllowedError` で拒否、非パスキー要求は元処理へ委譲され、多重注入でも無限再帰せず、設定ファイルでは終了状態を保持したまま保存・自動入力・翻訳バブルが無効化される。
- **AC-04 (車載ズーム既定 100% & Web フルスクリーン & 音量固定)**:
  - **Given** YouTube および一般動画ページ
  - **When** 未設定時の拡大率確認、REST/WS 経由での範囲外拡大率送信、およびフルスクリーン操作・動画プレイヤーミュート発生時をテストする
  - **Then** 拡大率既定は `100%` で `[50, 250]` クランプが REST/WS 双方で働き、フルスクリーン時は `screen` 寸法がウィンドウ寸法に一致してボタン無効化が回避され、動画プレイヤーは常にアンミュート・音量 100% に維持される。
- **AC-05 (プロセスツリー凍結/復帰順序)**:
  - **Given** 親子孫プロセスを持つブラウザ稼働状態
  - **When** 単一電源ドメインからの指示で凍結・復帰を実行する
  - **Then** `SIGSTOP` は末端から親へ、`SIGCONT` は親から末端へ送出されてプロセス状態が正しく遷移する。
- **AC-06 (managed policy による infobar 恒久抑止)**:
  - **Given** 稼働イメージのビルド定義
  - **When** `/etc/opt/chrome/policies/managed/` の policy ファイルと Chrome 起動引数を検査する
  - **Then** `CommandLineFlagSecurityWarningsEnabled: false` を含む JSON がイメージへ焼き込まれており、廃止済みで無効な `--disable-infobars` は起動引数に含まれない。
- **AC-07 (フルスクリーン保護・SPA 解除・ページ即時同期)**:
  - **Given** 単一ページスクリプトが注入された YouTube および一般動画ページ
  - **When** 仮想フルスクリーン中にプレイヤーがフルスクリーンボタンを `disabled` 化する／`yt-navigate-start` の SPA 遷移が発生する／`Page.frameNavigated`・`navigatedWithinDocument` イベントが発火する
  - **Then** ボタンは操作可能なまま（`disabled`/`aria-disabled` 除去・`pointer-events` 強制）で capture 位相タップが接続され、SPA 遷移で仮想フルスクリーン状態が自動解除されコメント欄等の装飾が残留せず、URL・タイトルは 3 秒ポーリングを待たずイベント即時で同期される。
- **AC-08 (PulseAudio 起動前・起動後自己修復)**:
  - **Given** stale ソケットまたは仮想シンク欠落（設定再読込等）が残存する起動環境
  - **When** 仮想オーディオ環境の初期化を実行する
  - **Then** stale ソケットと既存デーモンの掃除、`pactl load-module` によるシンク再ロード、既定シンク・音量 100%・ミュート解除強制が試みられた上で応答が得られ、自己修復後も無応答の場合のみ起動失敗となる。
