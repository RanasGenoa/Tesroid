# 仕様書 08: 観測性・メトリクス・詳細テレメトリ

## 1. 概要と目的

実車走行検証およびセルフホスト運用において、映像描画 FPS・ネットワーク RTT・実効ビットレート・符号付きの正確な A/V ドリフト・エンコーダ状態・通信停滞/同期イベントを定量的に記録・可視化・エクスポートできるようにし、現場特有の障害原因を迅速に特定する。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 品質メトリクス収集・集計・配信
- **収集指標（クライアント 10 秒ウィンドウ）**:
  - **ウィンドウ差分計測（10 秒ごとにリセット）**: 実描画 FPS（実際の `<canvas>` 描画完了時点で計測）、最小/最大 FPS、**ウィンドウ内ドロップフレーム数（同期維持のために映像側で破棄したフレームを含む）**、**ウィンドウ内デコーダエラー数**、受信映像パケット/バイト数、受信音声パケット数、実効ビットレート（kbps）、1 フレーム描画所要時間 p50 / p95（1 窓最大 1,200 サンプル）。
  - **累積補助計測**: 総描画フレーム数。
  - **瞬間スナップショット**: デコードキュー長、鮮度有効な RTT（5 秒超過時は `0`）、**丸め・クリップなしの符号付き A/V ドリフト（ms）**、表示幅・高さ・DPR。
- **送信・サーバー統計**:
  - メトリクス投入経路は **WebSocket 専用チャンネル (`0x14`) に一本化** し、クライアントは `10 秒` 周期で送信する（重複していた WS コマンドおよび HTTP POST 投入経路は廃止）。
  - サーバーは直近 **360 エントリ（約 1 時間分）** をメモリ内リングバッファに保持する。
  - サーバーは認証済みクライアントが存在する場合、**2 秒周期** でサーバー側統計（エンコード FPS、送出ビットレート kbps、音声 PPS、ブラウザ状態）を配信する。
- **REST API（閲覧・診断用）**:
  - `GET /api/metrics/summary`: 全保持サンプルの統計サマリ（サンプル数、計測時間秒、現在/平均/最小/最大 FPS、平均/最大 RTT、**10 秒窓差分値の合算による正確な総ドロップ数・総デコーダエラー数**、平均ビットレート、**符号付き平均 A/V ドリフトおよび先行/遅延が判別可能な統計値**、最終更新時刻）を返却（未計測時はすべて 0 値の空サマリ）。
  - `GET /api/metrics/history?limit=`: 時系列履歴を返却（既定 `60` 件、正の整数へサニタイズ）。
  - `GET /api/health`（公開）: 稼働状態、稼働時間、現在時刻、およびエンコーダ稼働状態（実行有無、バックエンド、動作モード、圧縮設定、x264 プリセット、ドライバ名、直近フォールバック理由・時刻、キャプチャ解像度、エンコード解像度）を返却する。
  - ※ メトリクスおよびテレメトリ REST API は、機密情報やサービス停止を伴わないためループバック接続の認証免除を維持し、外部 IP からの接続には Bearer トークンを必須とする。
  - ※ テスト音声出力機能（`POST /api/audio/test`）は不要のため仕様から完全削除する。

### 2.2 詳細テレメトリ（JSONL セッションログ）
- **クライアント収集（オプトイン・サーバー設定保存）**:
  - 既定は **無効（OFF）** とし、有効/無効フラグはサーバー設定に一元保存する（`localStorage` 不使用）。無効時はイベント記録・コンソールフック・フラッシュを行わずゼロオーバーヘッドとする。
  - 有効化時は `1,000 ms` 周期（キュー上限 `500` 件）で WS `0x15` チャンネルへ送信し、`console.warn` / `console.error` も再帰ガードおよび循環参照安全なシリアライズ付きで記録する。無効化時は停止前に最終イベント（`telemetry_disabled`）をフラッシュする。
  - 高頻度の同期微調整イベントは `500 ms` スロットル＋抑止件数カウンタで記録量を抑制する。
- **サーバー永続化 & ローテーション**:
  - セッション開始時はメモリ上で一意なセッション ID（`session-YYYYMMDD-HHMMSS-<ランダム>`）を発行するのみとし、**最初のイベントが実際に到着するまでディスク I/O を行わない（遅延ファイル作成）**。
  - 有効イベント検証: 非配列オブジェクトであり、文字列 `event` および許可種別（`av_sync`, `buffering`, `decoder`, `pacer`, `audio`, `network`, `log` — プロトコル型定義と完全整合）に一致するもののみ受理し、`sessionId` と `serverTimestamp` を付与してセッション単位の直列化書き込みキューで JSONL 追記する。
  - 容量・件数制限:
    - 1 回の WebSocket ペイロード上限: **512 KiB**（超過時は即破棄）。
    - 1 バッチ最大処理イベント数: **500 件**。
    - 1 セッションログファイル上限: **10 MiB**（超過後は上限到達フラグを立て以降の追記を拒否。再起動後も既存ファイル行数・サイズから状態を復元する）。
    - 保持セッション数上限: **15 セッション**（新規ファイル作成時に超過分を最古更新時刻から自動削除）。
- **テレメトリ管理 REST API**:
  - `GET /api/telemetry/sessions`: セッション一覧（ID、ファイルサイズ、行数、作成/更新時刻）を返却。
  - `GET /api/telemetry/sessions/latest/download` / `GET /api/telemetry/sessions/:sessionId/download`: NDJSON 形式（`application/x-ndjson`）でダウンロード。未存在時は HTTP `404`。
  - `DELETE /api/telemetry/sessions`: 全テレメトリセッションログを削除。

## 3. 非機能要件・制約条件

- **非有効時の負荷ゼロ**: テレメトリ設定が OFF の環境ではクライアント処理およびサーバー側ファイルシステムへの書き込みを一切発生させないこと。
- **ファイルシステム安全性**: セッション ID は英数字・アンダースコア・ハイフン以外の文字をサニタイズし、パストラバーサルを完全に防止すること。
- **コンソールフック安全性**: エラーオブジェクトや循環参照オブジェクトを記録しても例外や無限再帰を起こさないこと。

---

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **未計測状態でのサマリ要求**: 履歴が 0 件の場合でも例外を起こさず数値項目 0 埋め・`lastUpdated: null` の正常レスポンスを返す。
2. **ファイルサイズ上限（10 MiB）到達**: 到達後の追加イベントはディスクを圧迫しないよう安全に切り捨て、既存ファイルはダウンロード可能なまま保持する。
3. **未認証 WebSocket からのテレメトリ・メトリクス送信**: 認証完了前の `0x14` / `0x15` チャンネル送信は無視し、記録・永続化しない。
4. **存在しないセッションのダウンロード要求**: 不正または未存在のセッション ID に対しては HTTP `404` を返す。
5. **セッション削除中の書き込み競合**: 削除 API 実行時・追記時は直列キューおよびディレクトリ再構築によりファイル欠損エラーを防ぐ。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (10 秒差分メトリクス・符号付きドリフト・WS `0x14` 一本化)**:
  - **Given** クライアントのメトリクス収集器とサーバー側集計履歴
  - **When** 10 秒ウィンドウ内で描画・ドロップ（同期破棄含む）・デコーダエラー・5 秒超の A/V ドリフトを発生させ、WS `0x14` 経由で 360 件超報告する
  - **Then** 各ウィンドウの差分値が重複水増しなく正確にサマリ合算され、5 秒超ドリフトも符号付きのまま隠蔽されず集計され、360 件リング上限が維持される。
- **AC-02 (テレメトリ遅延作成・既定 OFF・種別整合)**:
  - **Given** サーバー設定で管理されたテレメトリ無効/有効状態
  - **When** 無効状態でイベントを発生させる／有効状態で `network` を含む全許可種別・コンソールエラーを送信する
  - **Then** 無効時はディスク I/O が一切発生せず、有効時は `network` を含む全種別が JSONL へ記録され、循環参照でクラッシュしない。
- **AC-03 (テレメトリ 10MiB 上限・15 セッションローテーション・API)**:
  - **Given** セッション上限・サイズ上限を設定したテレメトリ管理機能
  - **When** 10 MiB を超えてイベントを追記する／15 セッションを超えて新規作成する／一覧・特定・最新ダウンロード・削除を実行する
  - **Then** 10 MiB 超過後は追記が拒否され再起動後も件数が復元され、16 個目作成時に最古が削除され、各 API が正常応答（未存在時は 404）を返す。
- **AC-04 (認証境界・ペイロード上限)**:
  - **Given** 未認証クライアント・外部 IP・ループバック IP からのリクエスト
  - **When** 512 KiB 超のテレメトリ送信、未認証 WS からの送信、外部 IP vs ループバックからの `/api/metrics/*`・`/api/telemetry/*` 呼び出しを行う
  - **Then** 512 KiB 超および未認証 WS 送信は破棄され、外部からの無認証 API 呼び出しは HTTP `401` で拒否され、ループバックからの参照は許可される。
