# 仕様書 02: セッション管理・マルチディスプレイ

## 1. 概要と目的

自宅サーバー上の単一ブラウザに対して複数端末が同時に操作・競合する事故を防ぐ排他制御を提供しつつ、前席ディスプレイ（プライマリ）と後席モニター（セカンダリ）での同時視聴・後席事前待機（スタンバイ）を実現する。配信品質・制御・同期の基準はすべてプライマリを唯一絶対の正とし、セカンダリは追従・同期のみを行う。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 セッションロールと権限・状態定義
- **プライマリ (`PRIMARY`)**:
  - 同時に最大 **1 セッション** のみ存在する主制御端末であり、**配信基準の絶対的正（Single Authority）**。
  - 映像および音声の双方を受信し、画面リサイズ、配信品質・バックプレッシャー・追っかけ進捗・Buffer-Hold 発動判定・A/V 同期基準・配信リセット要求の主導権を持つ。
- **セカンダリ・視聴中 (`SECONDARY_STREAMING`)**:
  - プライマリ稼働中に複数接続可能な追従・同期端末。
  - 映像のみを受信し（音声パケットはサーバー側で抑止、クライアント側も無音維持）、画面リサイズ要求・配信基準判定・エンコーダリセット要求は無視される。
  - 自身の受信・消費位置をプライマリの配信判定へ影響させず、プライマリの再生位置メタデータ（PONG 経由）へ追従・同期する。操作・制御権限（タッチ・ナビゲーション等）は現状仕様どおり視聴中は許容し、待機中のみ遮断する。
- **セカンダリ・待機中 (`SECONDARY_STANDBY`)**:
  - プライマリ（および代理プライマリ）が存在しない状態で後席接続された場合の待機状態。
  - 映像・音声パケットはいっさい配信されず、スリープ中のブラウザやエンコーダを起床させない。
  - 切断要求・接続監視（PING/PONG 等）を除く操作・ナビゲーション・電源制御要求はすべてサーバー側で無視され、画面上には切断ボタンのみを備えた待機オーバーレイを表示する。
- **代理プライマリ (`ACTING_PRIMARY`)**:
  - プライマリの離脱後、視聴中のセカンダリから最大 **1 セッション** だけ昇格し、一時的にプライマリ権限（音声受信・設定変更後のヘッダ受信・リサイズ・電源復帰操作・配信基準主導権）を代行する状態。

### 2.2 認証ログイン・排他・引き継ぎの状態遷移
- **新規プライマリ PIN ログイン（生 PIN 送信）**:
  - 既存のプライマリが接続中であれば、既存ソケットへ競合通知（`SESSION_CONFLICT`）を送信した上でクローズコード **`4009`** で強制切断し、制御権を引き継ぐ。
  - 接続中のセカンダリセッションは切断せず維持する（無効化された古いプライマリ・不整合トークンのみ整理する）。
  - 代理プライマリが存在する場合は通常のセカンダリへ降格させ（`SESSION_ROLE_CHANGED`）、**サーバー側で映像・音声双方のエンコーダを同時にリセットして新しいストリーム世代 ID（`streamEpoch`）を発行し、クライアント側も映像・音声双方のデコーダを完全リセット** してクリーンに再同期させる。
  - 待機中のセカンダリが存在する場合はすべて視聴中（`PRIMARY_SESSION_STATUS { active: true }`）へ昇格させ、電源・ライフサイクル管理を通じてブラウザおよびエンコーダを稼働させ配信を開始する。
- **新規セカンダリ PIN ログイン（`SECONDARY:<pin>` 送信）**:
  - **UI 選択導線**: 状態 API（`GET /api/status`）で有効なプライマリが存在する場合（`hasActiveSession: true`）、PIN 画面に「メインとして接続」「2 台目として接続」の 2 ボタンを並べて表示する。メニューからはプライマリ有無にかかわらず常時「後席待機モードで接続」を選択できる。
  - プライマリが接続中であれば即座に `SECONDARY_STREAMING` として参加する（プライマリがライブ端から `300 ms` 以上後方をバッファ視聴中であれば、プライマリ確認済み PTS 付近から追っかけ開始）。
  - プライマリ不在かつ **代理プライマリが稼働中** の場合は参加を拒否し、`SESSION_CONFLICT` 通知の上クローズコード **`4009`** で切断する。
  - プライマリ・代理プライマリともに不在の場合は `SECONDARY_STANDBY` として接続を確立する（電源・ライフサイクル管理側で自動スリープ予約を調整する）。
- **トークン自動再接続（`TOKEN:<token>` 送信）**:
  - 無効または期限切れトークンは認証失敗（`AUTH_FAILED`）とし、クライアントはセッション情報を消去して PIN 画面へ戻る。
  - 同じトークンを保持する別ソケットが既に開いている場合は、新しい接続を正として旧ソケットをクローズコード **`4000`（同一セッション再接続による引き継ぎ置換）** で閉じる。
  - クライアントはコード `4000` を受信した場合、コード `4009`（他端末競合エラー）とは明確に区別し、自動再接続ループは停止しつつ、共有セッションストレージを破壊せずに「新しい接続（別タブまたは再接続）に引き継がれました」という専用案内画面と「再接続する／PIN 画面へ戻る」のタッチボタンを表示する。
  - 他のセッションが稼働中に、権限リストに存在しない別トークンで自動再接続してきた場合は、新規接続側を競合（`SESSION_CONFLICT` / クローズコード **`4009`**）で拒否する。
  - セカンダリトークンで再接続しプライマリが不在の場合: 直前まで代理プライマリかつ配信パイプライン稼働中（他に代理プライマリ無し）であれば代理プライマリとして復帰、直前が待機中またはパイプライン停止中であれば待機中として復帰、スリープ猶予中の瞬断であれば視聴中セカンダリとして復帰する。

### 2.3 切断・離脱猶予・自動昇格/降格ルール
- **明示的切断（事前切断コマンド送信またはクローズコード `1000`）**:
  - サーバーは該当トークンを許可セッション一覧から即時削除する。
  - 切断したのが最後の **プライマリ** であった場合、視聴中のセカンダリが存在すれば **即座に** 最初の 1 台を代理プライマリへ昇格させる（`SESSION_ROLE_CHANGED`）。視聴中セカンダリが無ければ電源・ライフサイクル管理へスリープ予約を通知する。
  - **代理プライマリの連鎖昇格は行わない**: 代理プライマリが明示切断した場合、他に視聴中セカンダリが残っていても次の代理プライマリへ連鎖昇格させず、電源・ライフサイクル管理側のスリープ予約・待機遷移フローへ委譲する。
  - クライアントは明示切断時にセッションストレージを消去し、コード `1000` で閉じて `50 ms` 後にページリロードして PIN 画面へ戻る。
- **ページ離脱・リロード（クローズコード `1001`）**:
  - 最後のプライマリがコード `1001` で切断し、かつ視聴中セカンダリが存在する場合は即時昇格を行わず、**3,000 ms（3 秒）の昇格猶予タイマー** を開始する。
  - 3 秒以内にプライマリが再接続すれば猶予を取り消し、役割交代やエンコーダ再起動を起こさず継続する。
  - 3 秒経過しても復帰しない場合、旧プライマリトークンを削除し、視聴中セカンダリを代理プライマリへ昇格させる。
- **一時的な回線断（上記以外のクローズコード、例: `1006`）**:
  - トークンは有効のまま保持し、自動スリープ猶予期間中は視聴中セカンダリへの配信を維持する（即座に昇格・待機化しない）。
  - 電源・ライフサイクル管理の自動スリープまたは Buffer-Hold 期限満了時点でプライマリ・代理プライマリ双方が不在であれば、配信パイプラインを停止し、すべての視聴中セカンダリを `SECONDARY_STANDBY`（`PRIMARY_SESSION_STATUS { active: false }`）へ移行させる。

### 2.4 プライマリ基準同期とバックプレッシャー分離
- **再生タイミング同期**: サーバーは `PONG` 応答にプライマリ基準情報（`primaryRenderedPts`・報告経過時間 `primaryFeedbackAgeMs`・`primaryTargetBufferMs`・`primaryMode`）を付与する。セカンダリはこの情報のうち鮮度が **5 秒未満**（かつローカル経過補正が `-1,000〜5,000 ms` の範囲内）のものだけを外部マスタークロックとして参照し、前席のスピーカーと映像のズレを抑える。
- **ライブジャンプ連動**: プライマリが配信リセットを実行した際、新しい `streamEpoch` のもとでセカンダリへも同期通知を配信し追従させる。
- **バックプレッシャーおよび判定の完全分離**: プライマリのソケット滞留・ACK 進捗・Buffer-Hold 発動/解除判定はプライマリ（または代理プライマリ）の数値のみを参照して決定する。セカンダリ回線の輻輳や切断・遅延は、プライマリおよびエンコーダ稼働状態にいっさい影響を与えない（セカンダリ側ソケットが詰まった場合はセカンダリ宛ての送出のみを独立してスキップする）。

## 3. 非機能要件・制約条件

- **終端クローズコードによる再接続抑止**: クライアントは WebSocket クローズコード `1008`（ポリシー違反）、`4000`（同一トークン置換）、`4009`（セッション競合）を受信した場合、自動再接続ループを停止しなければならない。それ以外の異常切断時は `min(1000 * 2^試行回数, 30000)` ms の指数バックオフで自動再接続を試みる。
- **二重音声再生防止**: 後席（セカンダリ）端末が車載スピーカーへ二重に音声を流さないよう、通常セカンダリは常時無音（音声パケット非送信）を維持する。

---

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **リロード猶予中（3 秒間）の PONG 基準**: プライマリがリロード等で一時離脱し猶予タイマー稼働中にセカンダリが `PING` を送った場合、サーバーは `primaryRenderedPts: null` および `primaryFeedbackAgeMs: null` を明示的に返し、セカンダリが古い基準 PTS で誤外挿しないようにする。
2. **待機中の電源状態通知上書き防止**: 後席が `SECONDARY_STANDBY` 中にブラウザ状態通知を受信しても、待機オーバーレイを通常再生やスリープ解除画面へ上書きしない。
3. **代理プライマリ昇格時のブラウザ自動再生ポリシー**: ユーザー操作イベント外で `ACTING_PRIMARY` へ昇格した直後はブラウザが音声再生を自動ブロックする場合があるため、昇格後最初の画面タップで音声再生をアンロックする導線・案内を確保する。
4. **切断時のローカルバッファ再生継続（一時切断サバイバル）**: 配信中に一時回線断が発生しても、クライアント側映像バッファに `250 ms` 超の残量があれば即リセットせず残バッファ分を再生継続し、再接続成功時は復帰する。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (単一プライマリ排他と強制引き継ぎ)**:
  - **Given** 端末 A がプライマリとして接続している状態
  - **When** 端末 B が同一トークンではなく生 PIN でプライマリログインする（または別トークンで自動再接続する）
  - **Then** 新規 PIN ログイン時は端末 A がコード `4009` で切断され端末 B へ引き継がれ、別トークン自動再接続時は端末 B がコード `4009` で拒否される。
- **AC-02 (同一トークン置換 4000 の案内分離)**:
  - **Given** 端末 A があるセッショントークンで接続中の状態
  - **When** 同一トークンを用いた新しい WebSocket 接続が到着する
  - **Then** 古いソケットはコード `4000` で閉じられて自動再接続を抑止し、他端末競合エラー（`4009`）ではなく引き継ぎ置換案内画面を表示する（新しいソケットは継続）。
- **AC-03 (セカンダリ追従同期・バックプレッシャー分離)**:
  - **Given** プライマリ端末が配信視聴中で、セカンダリ端末が同時参加している状態
  - **When** セカンダリがリサイズ要求を送る／セカンダリ側の回線が深刻に輻輳する
  - **Then** リサイズ要求は無視され、セカンダリの回線輻輳はプライマリの配信品質や Buffer-Hold 判定にいっさい影響せず、セカンダリはプライマリ基準 PTS に追従する。
- **AC-04 (後席スタンバイと自動視聴開始)**:
  - **Given** プライマリが未接続でブラウザが停止・スリープしている状態
  - **When** 後席端末が待機モードで接続し、その後前席端末がプライマリ接続する
  - **Then** 後席の接続時点ではブラウザ・エンコーダは起動せず操作・停止・再起動は無効化され待機表示となり、前席接続と同時に後席の待機が解除され映像配信が開始される。
- **AC-05 (代理昇格・連鎖昇格なし・降格時映像音声同時リセット)**:
  - **Given** プライマリと複数の視聴中セカンダリが接続中の状態
  - **When** プライマリが明示切断（コード `1000`）して 1 台目が代理昇格した後、（a）プライマリが再ログインする、または（b）代理プライマリが明示切断する
  - **Then** （a）では代理プライマリが通常セカンダリへ降格するとともに映像・音声双方のエンコーダ＆デコーダが同時リセットされ、（b）では 2 台目へ連鎖昇格せずスリープ・待機フローへ移行する。
- **AC-06 (一時通信断時の待機保護と自動スリープ移行)**:
  - **Given** プライマリと視聴中セカンダリが接続中で、プライマリが一時回線断（コード `1006` 等）になった状態
  - **When** 自動スリープ猶予時間未満で再接続するか、または猶予時間を超過して自動スリープが発動する
  - **Then** 猶予時間内はセカンダリの視聴が中断されず、自動スリープ発動時にセカンダリは待機モード（`PRIMARY_SESSION_STATUS { active: false }`）へ遷移する。
