# 仕様書 01: 認証・セキュリティ・初期セットアップ

> 関連: PR #102, Issue #101

## 1. 概要と目的

インターネットへセルフホスト公開される専用クラウドブラウザに対し、不正アクセスおよび総当たり攻撃を確実に遮断しつつ、テスラ車載ディスプレイのタッチ操作のみで迷わず初回導入・認証・接続復帰ができる認証およびオンボーディング基盤を提供する。

---

## 2. 機能要件（入力・処理・出力・状態遷移）

### 2.1 PIN 認証 & セッション管理
- **PIN 形式**:
  - 入力: 半角数字 `0〜9` のみで構成される 4〜8 桁の文字列（`^\d{4,8}$`）。
  - 保存: コスト係数 `10` の bcrypt ハッシュとして永続化し、平文の PIN は永続化および外部返却しない。
- **セッション発行・維持・失効**:
  - PIN 認証成功時、暗号学的に安全なランダム 32 バイト（64 文字の 16 進数文字列）のセッショントークンを発行する。
  - トークンの有効期限（TTL）は **24 時間（86,400,000 ms）** とし、期限切れトークンは検証時に拒否するほか、10 分周期でメモリ上から定期掃討する。
  - セッション状態はサーバーのメモリ上のみに保持し、サーバー再起動時はすべての既存トークンを失効させる。
  - クライアントは取得したトークンおよびセッションロールをブラウザのタブ単位セッションストレージに保持し、WebSocket 再接続時の自動再認証（`TOKEN:<token>`）および REST API の `Authorization: Bearer <token>` 認証に使用する。
- **エンドポイント認証境界**:
  - **認証不要（公開）**: システム状態取得（`GET /api/status`）、ヘルスチェック（`GET /api/health`）、ブラウザ状態取得（`GET /api/browser/status`）、初期セットアップ（`POST /api/setup`、完了後は 403）、PIN 検証（`POST /api/auth/verify`）、静的フロントエンド配信。
  - **Bearer トークン必須**: 設定取得・更新（`GET` / `PUT /api/settings`）、システム電源・ライフサイクル制御、ブラウザナビゲーション、配信リセット（`POST /api/stream/reset`）。
  - **ループバック免除（リモートは Bearer 必須）**: 品質メトリクス取得 API（`/api/metrics/*`）および詳細テレメトリ API（`/api/telemetry/*`）はループバック接続を免除し、外部接続には Bearer トークンを要求する。
  - **WebSocket（`/ws`）**: 未認証状態で認証チャンネル以外のメッセージを受信した場合は認証要求（`AUTH_REQUIRED`）を返す。セットアップ未完了状態で接続された場合でも、有効な 4〜8 桁 PIN が送信された場合は初回 PIN 登録・セットアップ完了としてそのままプライマリセッションを確立することを許容する。
- **PIN 更新（`PUT /api/settings`）**:
  - 入力が未指定または空文字の場合は現在の PIN を維持する。
  - 非空かつ 4〜8 桁の半角数字でない場合は HTTP `400` で拒否する。
  - 有効な更新時はハッシュを書き換え、連続失敗カウンタを `0` にリセットするとともに、**発行済みの既存セッショントークンをすべて即時失効** させる（接続中クライアントへ再認証を要求する）。
- **設定画面の再認証 UI**:
  - トークン未保持状態で設定画面を開く際の PIN 再認証は、ネイティブダイアログ（`window.prompt()`）を使用せず、画面上の **アプリ内ソフトウェア PIN テンキーモーダル** で統一する。

### 2.2 ブルートフォース・セキュリティロックアウト
- **状態定義と遷移**:
  - `NORMAL`（連続失敗回数 `0〜9`）→ PIN 検証失敗のたびに失敗回数を +1 し、最終失敗時刻とともにロックアウト状態ファイル（`lockout.json`）へ即時永続化する。
  - 連続失敗回数が **10 回** に達した時点で `LOCKED` 状態（`isLocked: true`）へ遷移し、`lockout.json` を永続化した上で接続中の全 WebSocket ソケットへポリシー違反クローズコード **`1008` (`POLICY_VIOLATION`)** を送信し、**200 ms 後** にサーバープロセスを終了コード `1` で強制停止する。
  - `NORMAL` 状態中に正しい PIN で認証成功した場合、または設定画面から有効な PIN に更新した場合は、連続失敗回数を `0`・`isLocked: false` へリセットする。
- **起動時ガード**:
  - サーバー起動時に `lockout.json` を検証し、`isLocked === true` または `consecutiveFailures >= 10` の場合は一切のサービスを提供せず即時終了コード `1` で停止する。ロック解除には管理者による **永続ボリューム内の `lockout.json` の削除およびその後のコンテナ再起動が必須** である旨を手順書および画面案内へ明記する。
- **クライアントのロックアウト検知と接続障害分離**:
  - PIN 入力画面では、残り試行可能回数が **5 回未満（1〜4 回）** になった時点で残回数表示を警告色（赤）へ切り替える。
  - 状態 API が `consecutiveFailures >= 10` を返却した場合、PIN 検証応答または WebSocket 認証失敗応答が `remainingAttempts <= 0` を返却した場合、もしくは WebSocket がクローズコード **`1008`** で切断された場合、クライアントは WebSocket を閉じてロックアウト画面へ遷移し、管理者向けの解除手順（`lockout.json` 削除が必須である旨）を表示する。
  - `GET /api/status` への通信がネットワーク障害またはサーバー停止により失敗した場合は、PIN 入力画面（残回数 10）へ誤フォールバックせず、「サーバーに接続できません（ロックアウト停止中または起動中の可能性があります）」の専用接続エラー画面（再試行ボタン付き）を表示する。

### 2.3 初期セットアップ & オンボーディング
- **画面フロー**:
  - 初回アクセス時（`isSetupCompleted === false`）は 2 ステップのセットアップウィザードを起動する。
    - **Step 1（オンボーディングガイド）**: 公的 CA による HTTPS/SSL 公開が必須である旨、アプリの基本機能概要、タッチ操作・仮想キーボード入力方法、常設 HUD の操作説明（`24 / 30 / 60 FPS`、`0.25M〜2.0M`）、後席待機モードの概要を案内する。
    - **Step 2（初期設定フォーム）**: 認証 PIN コード（必須・半角数字 4〜8 桁）、タイムゾーン（既定 `Asia/Tokyo`、ほか `UTC` / `America/New_York` / `America/Los_Angeles`）、品質・負荷 3 択を入力して `POST /api/setup` へ送信する（許可ドメイン項目および言語選択欄は設けない）。
  - 完了後は PIN 入力画面へ遷移する。オンボーディングガイド自体は PIN 入力画面の右上メニューからいつでもモーダルとして再表示できる。
- **初期セットアップ API（`POST /api/setup`）契約**:
  - `isSetupCompleted === true` の状態での呼び出しはすべて **HTTP `403`** で拒否する。
  - 必須の PIN が形式不正の場合は **HTTP `400`** を返す。
  - `timezone` は 64 文字以内の有効な IANA タイムゾーン文字列（`Intl.DateTimeFormat` で検証）のみ許可し、不正値・形式外が送信された場合は `PUT /api/settings` と統一して **HTTP `400`** で拒否する（未指定時は既定 `Asia/Tokyo`）。
  - システム表示言語は環境変数設定（既定 `ja-JP`）に従い、セットアップフォームからは変更しない。
  - `allowedDomains` 機能は仕様から削除する。
- **品質・負荷 3 択の一括初期設定（PR #102 / Issue #101 要件統合）**:
  - 初期セットアップ Step 2 に車両世代・環境に応じた **品質・負荷 3 択**（`最高品質 (MCU3)` / `標準 (MCU3) *既定*` / `軽量 (MCU2)`）を設け、新設定種別を増やさずサーバー側の既存設定項目（クライアント負荷プロファイル、サーバー映像パフォーマンスプリセット、初期 FPS・映像ビットレート、ブラウザ表示拡大率、**先行バッファ深度**）へ初期値を一括展開するショートカットとして動作させる。
  - 先行バッファ深度を含むすべての設定はサーバー側に一元保存し（車両ブラウザ側の `localStorage` は廃止）、クライアントは接続時にサーバーから読み出す。
  - 展開定義（3 択・大小文字無視トリム対応・未指定時は従来既定を維持・未知値は **HTTP `400`** で拒否）:
    - `最高品質 (high)`: GPU 環境は `high`（最大辺 1920・圧縮 4）/ CPU 環境は `cpu_balanced`（最大辺 1280・`veryfast`）、クライアント負荷 `standard`（等倍・FPS 選択肢 `[24,30,60]`）、初期 FPS `60`、映像ビットレート `2.0M`、表示拡大率 `100%`（既定）、先行バッファ深度 `10000 ms`。
    - `標準 (standard)`: GPU 環境は `balanced`（最大辺 1280・圧縮 7）/ CPU 環境は `cpu_balanced`、クライアント負荷 `standard`、初期 FPS `30`、映像ビットレート `1.0M`、表示拡大率 `100%`（既定）、先行バッファ深度 `10000 ms`。
    - `軽量 (lightweight)`: GPU 環境は `low_power`（最大辺 960・圧縮 7）/ CPU 環境は `cpu_low_power`（最大辺 960・`ultrafast`）、クライアント負荷 `lightweight`（倍率 `0.65`・FPS 選択肢 `[24,30]`）、初期 FPS `24`、映像ビットレート `0.5M`、表示拡大率 `70%`、先行バッファ深度 `2000 ms`。
  - セットアップ保存後、稼働中のブラウザ表示拡大率・エンコーダ設定・エンコード出力寸法へ即時反映する。各反映処理は互いに障害分離し、いずれかまたは複数が失敗してもセットアップ完了（HTTP `200`）は成功させる。
  - UI 上に「この選択は設定画面内の各項目の初期値をまとめて設定するショートカットであり、セットアップ後も設定画面からいつでも個別に変更可能である」旨を明記する。

## 3. 非機能要件・制約条件

- **完全タッチオンリー制約**: 車載画面には物理キーボードやマウスが存在しないため、PIN 入力、設定再認証 PIN モーダル、セットアップウィザード、オンボーディングガイドの操作・モーダル閉じはすべて画面タップのみで完結しなければならない。ネイティブ `window.prompt()` / `window.confirm()` を使用してはならない。
- **WebCodecs セキュアコンテキスト要件**: クライアントは公的 CA 証明書による HTTPS / WSS 配信を前提とし、初回ガイドでその要件を明確に案内する。
- **機密非露出**: 平文 PIN およびトークンはログ、エラー応答、ステータス API に出力しない。

## 4. 判明しているエッジケースとエラー時の振る舞い

1. **セットアップ未完了時の PIN 検証要求（`POST /api/auth/verify`）**: 認証は HTTP `401` で拒否するが、まだ PIN が設定されていないためブルートフォース失敗回数は加算しない。
2. **空または欠落した PIN での検証要求**: リクエスト不正として HTTP `400` を返し、失敗回数は加算しない。
3. **非空かつ形式外の PIN での検証要求**: 試行消費として失敗回数を加算し HTTP `401`（残回数付き）を返す。
4. **設定ファイルの JSON 破損**: 起動時に設定ファイルが破損していた場合、デフォルト設定へフォールバックし、PIN 未設定の初期セットアップ状態から安全に再起動できるようにする。
5. **ソフトウェアエンコーダ環境で品質 3 択の「最高品質」選択時**: VAAPI 固有のパラメータをエンコーダへ渡さず、有効な CPU プリセットへ安全にマップする。
6. **ロックアウト中の再起動・通信不能**: ロックアウト時は `1008` クローズまたは `lockout.json` 起動ガードで停止し、クライアントは誤って残回数 10 の入力画面へ戻らず接続エラー／ロックアウト画面へ留まる。

## 5. 受け入れ条件（テスト観点）

- **AC-01 (PIN 形式制約 & 変更時トークン全失効)**:
  - **Given** 初期セットアップまたは設定変更で PIN を送信するとき、および既存セッションが接続中の状態
  - **When** 3 桁・9 桁・英字・記号・全角数字など `^\d{4,8}$` に一致しない値を送信する／正しい形式の新しい PIN へ変更する
  - **Then** 形式外は HTTP `400` で拒否され、4〜8 桁の半角数字のみ受理され、有効な PIN 変更後は発行済みの全セッショントークンが即時失効する。
- **AC-02 (セッション TTL と WebSocket 初回設定)**:
  - **Given** 正しい PIN で認証しセッショントークンを取得した状態、および未セットアップ状態で WebSocket へ直接 4〜8 桁 PIN を送信した場合
  - **When** 24 時間以上経過した後に同じトークンで再認証を試みる／未セットアップ状態で有効 PIN を WS 送信する
  - **Then** 期限切れトークンは拒否され、未セットアップ時の WS 有効 PIN は初期設定完了としてプライマリセッションを確立する。
- **AC-03 (ブルートフォース保護・クローズコード 1008・永続ロック)**:
  - **Given** セットアップ完了後の運用状態
  - **When** 誤った PIN を連続して 10 回入力する、または `/api/status` が通信不能となる
  - **Then** 5 回未満で警告表示となり、10 回連続失敗で接続ソケットへコード `1008` を送出して `lockout.json` 永続化後に終了コード `1` で停止し、`lockout.json` 削除まで起動不可となり、`/api/status` 通信不能時は専用エラー画面を表示する。
- **AC-04 (セットアップ完了後 403 ガード & 不正入力 400 統一)**:
  - **Given** 未セットアップおよびセットアップ完了後のサーバー
  - **When** 未完了時に不正 `timezone` や未知 `qualityPreset` を送信する／完了後に `POST /api/setup` を再実行する
  - **Then** 未完了時の不正値は HTTP `400` で拒否され、完了後の再実行は HTTP `403` で拒否される。
- **AC-05 (品質 3 択のサーバー一元展開と他端末同期 — PR #102)**:
  - **Given** 未セットアップ状態のサーバー（VAAPI 稼働またはソフトウェア稼働）
  - **When** 別端末から `POST /api/setup` で `lightweight` を選択して完了し、その後車載ブラウザで接続する
  - **Then** サーバー設定へ負荷プロファイル・CPU/GPU 適合プリセット・FPS・ビットレート・拡大率・先行バッファ深度（`2000 ms`）が一元保存され、車載ブラウザ接続時にサーバーから同一設定が読み出され、一部ライブ反映が失敗してもセットアップ応答は HTTP `200` で完了する。
- **AC-06 (タッチ専用再認証モーダル & オンボーディングガイド)**:
  - **Given** 未認証状態で設定ボタンを押下したとき、および PIN 画面・初回ステップ 1
  - **When** 設定アイコンをタップする／ガイド表示と閉じ操作を行う
  - **Then** `window.prompt()` は一切表示されずアプリ内ソフトウェア PIN テンキーモーダルが表示され、ガイドはタップのみで遷移・開閉できる。
- **AC-07 (静的フロントエンドの公開配信)**:
  - **Given** ビルド済みクライアント（`client/dist`）が配置されたサーバーと、Bearer トークンを保持しない未認証状態
  - **When** `GET /`、`GET /assets/index-<hash>.js`、および API 以外の未知パスをそれぞれ実行する
  - **Then** `/` は `index.html` を HTTP `200`・`text/html`・`Cache-Control: no-cache`（每次都座検定）で返し、認証を要求しない。ハッシュ付き assets は HTTP `200`・正しい MIME・長期不変キャッシュ（`max-age=31536000, immutable`）で返す。API 以外の未知パスは JSON `404` のまま据え置き、ディープリンクの SPA 書き換えは行わない。
